## Command mechanics

Three helpers write a business change, an audit row and an idempotency receipt in one mutation. They share request fingerprinting (`fingerprintArguments`), the replay decision (`checkIdempotency`), the receipt digest (`resultIdentityDigest`/`verifiedResultIdentity`) and `writeIdempotencyRecord` from `convex/lib/idempotency.ts`. Their policies differ deliberately:

| Behavior                 | Finished goods `command()`                             | HR `hrCommand()`                                                                 | Master data `create/update/deleteMasterDataRow` |
| ------------------------ | ------------------------------------------------------ | -------------------------------------------------------------------------------- | ----------------------------------------------- |
| Request ID               | Non-blank, ≤ 200 chars                                 | `^[A-Za-z0-9_-]{8,64}$`                                                          | Not checked by the helper                       |
| Actor in fingerprint     | Only `finishedGoods.move.*` and `finishedGoods.scan.*` | Always                                                                           | No                                              |
| Changed payload, same ID | `REQUEST_ARGUMENT_CONFLICT`                            | `REQUEST_ARGUMENT_CONFLICT`                                                      | `REQUEST_ARGUMENT_CONFLICT`                     |
| Replay answer            | Stored document ID                                     | Rebuilt by the feature's `replay()` under current access; refused if unavailable | Stored ID, only if the target row still exists  |
| Missing receipt digest   | Unverifiable                                           | Unverifiable                                                                     | Accepted (older receipts)                       |
| Retired request          | —                                                      | Actor-scoped fence returns `REQUEST_RETIRED`                                     | —                                               |
| Refusal                  | Returned with a DENIED audit row                       | Returned with a DENIED audit row                                                 | Returned as `Result`                            |

On the client, `useAsyncOperation` gets its request ID from `useRequestIdentity`, which keeps one ID per payload key in draft storage (`fg-requests:<scope>`) until `clearRequests()`, so a retry after a lost response reuses it. `useHrWrite` goes further: a module-level owner per command survives remounts while the promise is pending, and session storage keeps the request ID, payload and expected revision so a later mount can resend or reconcile the uncertain write instead of minting a new ID. Malformed stored recovery data is never read as a fresh command. Keep these separate unless both policies change together.

## Projections inside tenant mutations

Finished-goods and storage-layout source rows (`PROJECTED_SOURCE_TABLES` in `convex/lib/schemaPolicy.ts`: locations, layout rows, products, batches, units, placements, moves, job scans) have derived rows maintained in the same transaction: unit contributions, product summaries, warehouse totals, zone occupancy and surfaces, catalogue signals, change shards and search indexes.

- The owner is `inventoryWriter` (`convex/lib/inventoryWriter.ts`). It composes `trackFinishedGoodsWrites` and then `trackSearchIndexWrites`, and flushes them in that order before the mutation returns.
- Every finished-goods and storage-layout tenant mutation declares `writer: inventoryWriter`, so its projection effects are visible in its definition.
- `mutationWithOrg` (`convex/lib/tenantFunctions.ts`) knows only the generic `TenantWriteOwner` contract. When a mutation declares no writer, its handler database refuses writes to those tables, and the whole transaction fails. HR, AI-usage and workspace mutations declare no writer and cannot reach the projection modules (`module-boundaries` test).
- Raw internal writers (staging seeds, operational migrations, backfills) bypass `mutationWithOrg`. Each is named with its reason in `module-boundaries` ("names every raw writer…"). Seeds rely on `scripts/seed-local-test.mjs` running the totals, occupancy and search backfills afterwards.

## Supported HR sizes

| Limit                                           | Value                                     | Source                                                                                                                              |
| ----------------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Period length                                   | 31 business dates                         | `MAX_PERIOD_DAYS`, `convex/model/hr/period.ts`                                                                                      |
| Single-read draft preview and one-command close | 50 employees                              | `MAX_PREVIEW_EMPLOYEES`; larger rosters use the staged close ([hr-period-staged-close.md](../operations/hr-period-staged-close.md)) |
| Staged close step                               | 25 employees, ≤ 100 roster documents      | `convex/hr/periodClose.ts`                                                                                                          |
| CSV export part                                 | ≤ 2,000 rows, never splitting an employee | `hr/periods:exportCsv`                                                                                                              |
| Re-certifications kept per day                  | 50, then `CERTIFICATION_HISTORY_LIMIT`    | `MAX_CERTIFICATION_HISTORY`, `convex/hr/review.ts`; also enforced in `convex/hr/leave.ts`                                           |
| Sites per scope / employees per site list       | 50 / 99                                   | `MAX_SCOPE_SITES`, `MAX_SITE_EMPLOYEES`, `convex/hr/shared.ts`                                                                      |

These are local-fixture limits, not production measurements. Raise one only with a measured transaction budget and a failure model.
