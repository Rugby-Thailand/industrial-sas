Reading guide

ใช้รูปแบบ FigJam เป็น reference ไม่ใช่ requirement

บอร์ดตัวอย่างใช้ swimlane แยก Customer, Sales, Design/Engineer, Customer Service, Purchasing, Production, Inventory และ QA/QC พร้อม branch “มี stock / ต้องผลิต / ต้องออกแบบใหม่” เอกสารนี้รักษาแนวคิดดังกล่าว แต่ปรับ flow ให้มี control และ inventory accounting ที่ implement ได้จริง

กล่องขาว = งานของคนกล่องดำ = system transactionเส้นประ = decisionเทา = exception / recoveryลูกศร = handoff

คำศัพท์ที่ต้องยืนยันกับหน้างาน

ในบอร์ดมี FO, SO, PO และ Master Card เอกสารนี้ตีความชั่วคราวว่า FO = Factory/Production Order, SO = Sales Order, PO ฝั่งลูกค้า = Customer PO และ PO ฝั่งจัดซื้อ = Purchase Order จึงต้องใช้ prefix/เลขที่ต่างกันในระบบเพื่อลดความสับสน

02
Flow design contract

กฎที่ทุก diagram ต้องรักษา

G-01
มี owner เดียวต่อ step. ผู้ทำ ผู้ตรวจ และผู้อนุมัติแยกกันเมื่อความเสี่ยงสูง
G-02
Decision ต้องมีครบทุกทางออก. ใช่/ไม่ใช่, partial, rejected, cancelled และ retry ต้องไปจบที่สถานะที่รู้ได้
G-03
Document status ไม่ใช่ stock status. เอกสาร Completed ไม่ได้แปลว่า Stock Available จนกว่า QC/ledger/putaway เสร็จ
G-04
ทุก stock change ผ่าน ledger. ระบบธุรกิจสร้าง command; inventory ledger เป็นผู้ post movement และ balance projection
G-05
Handoff ใช้ event + reference. ส่ง ID และ snapshot ที่จำเป็น ไม่ให้โมดูลหนึ่ง patch ตารางของอีกโมดูล
G-06
Exception เป็น flow จริง. short, over, damage, hold, reject, rework, offline และ duplicate มี recovery/approval ไม่ใช่เพียง error toast
