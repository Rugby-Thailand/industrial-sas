## ข้อสรุป

**จัดหน้าตามงาน 3 แบบ แล้วเปิดเครื่องมือให้ตรงกับงานที่กำลังทำ** ตามที่ผู้ใช้ยืนยันว่าทุกงานสำคัญ ไม่ลดหน้าให้เหลือเพียงการค้นหา

1. **ค้นหาและดูของ:** ช่องค้นหาชัดเจน ปุ่มแผนผัง/รายการมีข้อความ เลือกตำแหน่งแล้วเห็นสินค้าในแผงเดียว
2. **จัดเก็บ / ย้าย:** เห็นของเข้ารอจัดเก็บ และปุ่มย้ายต่อหน่วย แสดงขั้นตอนจอง รับของ ตรวจปลายทาง และยืนยันจนจบ
3. **แก้ไขผัง:** มีสถานะแบบร่าง บันทึก/ยกเลิก และป้องกันการออกจากงานโดยเผลอทิ้งข้อมูล

ใช้ภาพรวม PD ตามสัดส่วนจริงคู่กับภาพขยายกลุ่ม เพื่อไม่ต้องแตะ 198 ช่องเล็ก ๆ ในภาพเดียว ภาพขยายรักษาจำนวนแถวและลำดับตำแหน่ง แต่ปรับขนาดช่องให้กดง่าย จึง **ไม่ใช่ภาพวัดระยะ**

## หลักฐานและเหตุผล

- ตรวจหน้าที่ผู้ใช้ส่งจริงในสถานะล็อกอิน: toolbar รวมตัวเลือกหลายระดับ ไอคอนหลายตัวไม่มีข้อความ ช่องที่ตรวจบนผังประมาณ 27 × 17 CSS px และมีพื้นที่ว่างใต้ผังมาก [บันทึกการตรวจ](research/live-observations.md)
- การเก็บเครื่องมือเฉพาะงานไว้ในบริบทที่เกี่ยวข้องสอดคล้องกับ [NN/g — Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) และ [Complex Applications](https://www.nngroup.com/articles/complex-application-design/)
- ป้ายข้อความช่วยลดการเดาความหมายของไอคอน [NN/g — Icon Usability](https://www.nngroup.com/articles/icon-usability/)
- [W3C — Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) กำหนดขั้นต่ำ 24 × 24 CSS px พร้อมข้อยกเว้น; เป้าขนาดสัมผัสที่ใหญ่ขึ้นเป็นการตัดสินใจออกแบบเพิ่มเติม
- งานนี้เป็นการตรวจโดยผู้เชี่ยวชาญและต้นแบบ ยังไม่ใช่ผลทดสอบความเร็วหรือความพึงพอใจกับพนักงานจริง

[รายงาน Kiro ฉบับแรก](research/kiro-research.md) เปรียบเทียบ 3 ทางเลือกและแผนเชื่อมคอมโพเนนต์ โดยเขียนก่อนผู้ใช้ยืนยันว่าทั้งสามงานสำคัญ สมมติฐาน lookup-first และรายละเอียดบางอย่างในรายงานแรกจึงถูกแทนที่ด้วยข้อสรุปในหน้านี้

[ภาคผนวกงานจัดเก็บ/ย้ายโดย Kiro](research/operations-addendum.md) อ้างอิง state machine และสิทธิ์จาก `MoveScreen`, `PlacementEditor`, `StorageZonesPanel` และ `convex/finishedGoods/workflow.ts`

## ลองทำอะไรใน preview

- ค้นหา `PD-L1-1`, สลับผัง/รายการ, เลือกกลุ่ม L1–L12 และกรองสถานะ
- เลือก **จัดเก็บ / ย้าย** → `PD-L1-1` → ย้าย `U-1001` → ปลายทาง `PD-L1-2` → จอง → ยืนยันรับของ → พิมพ์รหัสปลายทาง → ยืนยันวางแล้ว
- เลือก **จัดเก็บของเข้า** → `U-NEW-01` → เลือกช่องว่าง → จอง → ตรวจรหัสปลายทาง → ยืนยันจัดเก็บ
- เลือก **แก้ไขผัง** → ช่องว่าง → เปลี่ยนชื่อ/ความสูง → บันทึก หรือสลับงานเพื่อทดลองตัวป้องกันการทิ้งแบบร่าง
- ทดลองรีเซ็ต, ชั้น 2 ที่ว่าง, รหัสค้นหาที่ไม่มี, ภาษา EN, ธีมมืด และจอมือถือ

## นำไปพัฒนาจริงเป็นระยะ

| ระยะ | สิ่งที่จะทำ | โค้ดหลัก |
| --- | --- | --- |
| 1 | แยกทางเข้างาน 3 แบบ เปลี่ยน Active เป็นป้าย ย้ายการเปลี่ยนสถานะไปตั้งค่าอาคาร เพิ่มชื่อปุ่มผัง/รายการ | `BuildingModelWorkspace`, `FloorWorkspaceToolbar`, `BuildingStatusToggle` |
| 2 | ภาพรวม+กลุ่มขยาย ใช้ selection และรายละเอียดชุดเดียวระหว่างมุมมอง มือถือเริ่มจากรายการเมื่อ URL ไม่ระบุ | `FloorMap`, `FloorMapDrawing`, `FloorPositionDetail`, `FloorLocationTable`, `LocationDetailsHost` |
| 3 | เชื่อมจัดเก็บ/ย้ายกับ flow เดิม พร้อมกลับมาที่ตำแหน่งและงานค้าง | `StorageZonesPanel`, `MoveScreen`, `DestinationPicker`, `PlacementEditor` |
| 4 | เชื่อม editor ชั้น/โซนและ guard เดิม ทดสอบสิทธิ์ ข้อมูลเก่า URL และข้อมูลไม่ครบ | `FloorForm`, `useNavigationGuard`, `useCanManage`, `useWorkspaceQuery` |

ไม่เปลี่ยน schema หรือสร้าง mutation ทางลัด การจอง การคืนต้นทาง การยืนยันและสิทธิ์ต้องใช้กฎฝั่งเซิร์ฟเวอร์เดิมทั้งหมด รวมทั้ง owner, stale checks และ request idempotency ต้องรักษา QR, 3D, split, การเพิ่มชั้น/โซนและพื้นที่สงวนผ่านทางเข้ารอง และให้ลิงก์ `floor/view/panel/editing/editZone` เดิมยังทำงาน

ก่อนนำขึ้นจริง ทดสอบพนักงานด้วยงานค้นหา 1 งาน จัดเก็บ 1 งาน ย้าย 1 งาน และแก้ไข/ยกเลิก 1 งาน เปรียบเทียบอัตราสำเร็จ เวลา คลิกผิด และการบันทึกโดยไม่ตั้งใจ กับหน้าปัจจุบัน เป้าหมายทั้งหมดต้องตั้งบน baseline จริง

## ขอบเขตและข้อจำกัด

- รูปทรงชั้น 1 มาจาก `pdApprovedPlan.ts` revision `PD-61500-11960-2026-09-27-r1`: 198 ตำแหน่ง / 12 กลุ่ม ข้อมูลสต็อกและชั้น 2 เป็นข้อมูลสาธิต
- การเปลี่ยนแปลงอยู่ในหน่วยความจำของแท็บ รีโหลดจะกลับเป็นข้อมูลเริ่มต้น ไม่มีการเขียนไป production
- แบบจำลองปลายทางเลือกเฉพาะช่องว่าง ไม่คำนวณ fit/overlap/support จริง การย้ายในต้นแบบเลือกเส้นทางตรวจรหัสเสมอ แม้ flow จริงอนุญาต acknowledgment บางกรณี
- โหมดแก้ผังจำลองชื่อ/ความสูง พร้อมล็อกความสูงเมื่อมีของ/การจอง ไม่จำลองการลากขอบเขต เพิ่มโซน เพิ่มชั้น สร้าง QR สแกนกล้อง หรือ 3D
- ตัวกรองสถานะเป็นการเลือกหนึ่งสถานะ ตำแหน่งเดียวอาจมีหลายสถานะ จำนวนในชิปจึงไม่ใช่ส่วนที่บวกกันเป็นทั้งหมด
- คำ UI เปลี่ยน TH/EN ได้ ชื่อสินค้าเป็นข้อมูลตัวอย่างและคงภาษาที่สร้างไว้
- งานรีเสิร์ช Kiro สองรอบสำเร็จ Parent หยุดรอบสร้าง HTML ที่ยังไม่เขียนไฟล์ แล้วประกอบ HTML ต่อจากผลรีเสิร์ชเพื่อรวมคำยืนยันล่าสุดของผู้ใช้ครบทั้งสามงาน
