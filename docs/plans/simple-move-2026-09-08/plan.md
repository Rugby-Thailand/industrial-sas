# ย้ายพาเลทด้วย checkbox — แผนและแบบหน้าจอ

วันที่: 2026-09-08 · สถานะ: ออกแบบเท่านั้น ยังไม่แก้แอปหรือยืนยันการย้ายจริง

## ปัญหาที่ตรวจพบ

หน้าปัจจุบันของ P-000001 อยู่ IN_TRANSIT แล้ว จึงมีช่องรหัสปลายทาง ไม่ใช่รหัสพาเลท การกรอก P-000001 ทำให้ขึ้นรหัสไม่ตรงกับปลายทาง ส่วนฟอร์มยืนยันถูกภาพ 3D ดันลงไปด้านล่าง ผู้ใช้ต้องการย้ายให้ง่ายโดยใช้ checkbox

## Flow ที่เสนอ

เลือกปลายทางและพิกัด → จองปลายทาง → ติ๊กว่ารับพาเลทแล้ว + เริ่มย้าย → ติ๊กว่าวางที่ปลายทางแล้ว + ยืนยันย้ายเสร็จ → แสดงตำแหน่งใหม่

ผู้ที่อยู่ IN_TRANSIT อยู่แล้วเข้าขั้นยืนยันวางทันที ไม่ต้องเริ่มใหม่หรือจองซ้ำ

### 1. จองแล้ว / รอรับพาเลท

- แสดงพาเลท สินค้า จำนวน ต้นทาง และปลายทางแบบสั้น
- Checkbox เริ่มต้นไม่ติ๊ก: “ฉันรับ P-000001 จากต้นทางแล้ว”
- ปุ่มหลัก “เริ่มย้าย” เปิดใช้งานเมื่อติ๊ก
- ไม่บังคับพิมพ์รหัสหรือสแกน QR
- เปลี่ยนปลายทางและยกเลิกได้ก่อนเริ่มย้าย

### 2. กำลังย้าย / รอยืนยันวาง

- กล่องยืนยันแสดงชื่อจุดจัดเก็บ อาคาร ชั้น รหัสตำแหน่ง X/Y/Z และทิศทาง ถ้าซ้อนต้องแสดงพาเลทรองรับด้วย
- Checkbox เริ่มต้นไม่ติ๊ก: “ฉันวาง P-000001 ที่ปลายทางนี้แล้ว”
- ปุ่มหลัก “ยืนยันย้ายเสร็จ” เปิดใช้งานเมื่อติ๊ก ไม่เปิดหน้าต่างถามซ้ำ
- สแกน QR อยู่ในส่วนพับ “สแกน QR เพิ่มเติม (ไม่บังคับ)”
- หากเลือกสแกนแล้วรหัสผิด แสดงเหตุผลและให้สแกนใหม่ หรือเลือกกลับไปยืนยันด้วยตนเองอย่างชัดเจน ไม่ตีความว่ารหัสผิดผ่านแล้ว
- คืนต้นทาง: แสดงต้นทางเดิมใน dialog พร้อม checkbox “ฉันนำพาเลทกลับต้นทางแล้ว” และปุ่ม “ยืนยันคืนต้นทาง” ใช้การยืนยันด้วยตนเองเช่นกัน
- ไม่ใช้ปุ่มยกเลิกหลังรับพาเลทแล้ว เพราะมีการเคลื่อนย้ายจริง

### 3. ย้ายสำเร็จ

- อัปเดตตำแหน่งจริง แสดง “ย้ายสำเร็จ” พร้อมปลายทางใหม่
- คืนพื้นที่ต้นทางและปลดล็อกพาเลทรองรับต้นทางตามกฎเดิมเมื่อไม่มีหน่วยอื่นพึ่งพา
- จำนวนสินค้าและชุดจัดเตรียมไม่เปลี่ยน

## หน้าจอ

- Desktop: ข้อมูลสรุปสั้นด้านบน แผนผังประมาณ 55–60% กล่องยืนยันด้านขวา มองเห็น checkbox และปุ่มตั้งแต่แรก
- Mobile: แสดงปลายทางก่อน แผนผังย่อด้านล่าง แถบ checkbox และปุ่มติดด้านล่าง ใช้ safe-area padding และสำรองพื้นที่ไม่บังเนื้อหา
- หนึ่ง checkbox และหนึ่งปุ่มต่อขั้น ไม่มีรหัสบังคับ ไม่มี banner สถานะซ้ำหลายชั้น
- ปุ่ม disabled ต้องมีเหตุผล “ติ๊กยืนยันหลังวางพาเลทแล้ว” ไม่ปล่อยให้ผู้ใช้เดา
- ขณะบันทึกปิดปุ่มซ้ำ; หากล้มเหลวคงข้อมูลและแสดงลองใหม่ หากข้อมูลปลายทางเปลี่ยนต้องตรวจใหม่และล้าง checkbox
- ภาษาไทย/อังกฤษ ใช้ข้อความปุ่มชัดเจน ไม่ใช้ไอคอนอย่างเดียวสำหรับการยืนยันหลัก

## งานฝั่งระบบ

1. แยก physical acknowledgement ออกจากการตรวจ QR ใน startMove, completeMove และ returnMove ภายใน convex/finishedGoods/workflow.ts
2. เพิ่ม confirmation แบบ explicit เช่น { kind: "ACKNOWLEDGEMENT", physicalConfirmed: true } และแบบ QR ที่อ้างหลักฐานการตรวจที่ถูกต้อง ห้ามส่ง code ของปลายทางให้อัตโนมัติเพื่อหลอกว่าผู้ใช้สแกนแล้ว
3. บันทึกวิธี ACKNOWLEDGEMENT พร้อมผู้กระทำ เวลา moveId พาเลท และตำแหน่งต้นทาง/ปลายทาง แยกจาก SCAN และ MANUAL ที่หมายถึงการกรอกรหัส
4. Server ตรวจสิทธิ์ warehouse เจ้าของรายการ move สถานะปัจจุบัน และเป้าหมายที่ถูกจอง จากข้อมูลจริง ไม่เชื่อพิกัดจาก client
5. รักษาการตรวจชน ขอบเขต ความสูง การรองรับ การจองพร้อมกัน และล็อกฐานเดิม ไม่เพิ่มกฎน้ำหนักในงานนี้
6. Complete และ return ทำการย้าย/ปล่อยล็อกแบบ atomic และรองรับ requestId ซ้ำโดยไม่บันทึกซ้ำ
7. รายการเก่าที่ RESERVED/IN_TRANSIT ต้องทำต่อได้ หลักฐาน QR เก่ายังอ่านได้ ไม่ย้ายตำแหน่งหรือเปลี่ยนจำนวนเพราะ migration
8. ปรับ type/schema/audit metadata เท่าที่จำเป็นและ client API types ให้ตรงกัน ไม่เปลี่ยน verification flow ของการรับจัดเก็บใหม่ที่อยู่นอกงานย้าย

## ลำดับ implement และตรวจรับ

1. เพิ่ม contract กับ backend tests สำหรับ acknowledgement ก่อนแก้ UI
2. ปรับ UI reserved/in-transit/return ให้หนึ่ง checkbox + หนึ่งปุ่มตามขั้น; ตรวจ active move เก่าของผู้ใช้ให้ทำต่อได้
3. ทดสอบไม่ติ๊ก, request ปลอม, ผู้ใช้ไม่มีสิทธิ์/คนอื่นเป็นเจ้าของ, target stale, ชน/ความสูง/stack lock, สแกนผิดและเปลี่ยนวิธี, cancel ก่อนรับ, return หลังรับ
4. ทดสอบ double click, retry, refresh ระหว่างทำงาน, สำเร็จแล้ว refresh, การจองพร้อมกัน โดยไม่เพิ่มจำนวนหน่วยหรือสินค้า
5. Browser QA ไทย/อังกฤษ desktop/mobile: เห็นปุ่มโดยไม่ต้องเลื่อนผ่านภาพสูง; checkbox ใช้ keyboard ได้; ไม่มีเนื้อหาถูกแถบล่างบัง
6. รันชุดทดสอบรวมและ production build เก็บ screenshots และวิดีโอด้วยบัญชีทดสอบ แอปยังอยู่ port 3100
