# Shared navigation and workflow core

## Goal

Make Back, scan navigation, URL state, and write completion reliable while deleting duplicated maintenance logic. This is a behavior-preserving refactor with regression fixes, delivered as one reviewable PR in an isolated worktree based on origin/main a050a851. The original working directory contains unrelated uncommitted work and must remain untouched.

## Evidence and current seams

The earlier scan investigation reproduced lost app history depth and draft markers after Next replaces a same-URL entry, an unmanaged fragment traversal leaving route progress active, duplicate no-op query entries, and query-only navigation hiding the whole page. Its local production checks passed after fixes, but those fixes are not yet on this base. Reapply only relevant fixes and tests; do not copy whole dirty feature files.

The current base still puts the shared navigation guard under storageLayouts although the shell, HR and finished goods use it. It owns browser listeners and a buffer in each hook instance, while programmatic guards are separately registered in lib/navigationGuard. Save completion can start navigation before the pending guard's asynchronous buffer removal completes. Catalogue hooks independently implement URL snapshots, fallback preferences, baseline pinning, subscriptions, and typing history. Async operations and HR writes each implement duplicate/stale-result lifecycle logic, with different outcome and retry semantics.

## Resolved Kiro review decisions (revision 2)

Kiro's first review returned REVISE with six blockers. The following decisions replace ambiguous portions of the proposed commits above. The review is retained with the delivery evidence.

1. **Base-specific behavior:** this base has only beforeunload protection in finished goods. Add the shared in-app guard to JobScan explicitly: dirty tickets, pending mutation, discard clears tickets and revokes preview URLs. Other finished-goods editors retain their existing feature dialogs in this PR to avoid double prompts. Their successful write side effects still migrate to the current-completion seam. Record broader editor adoption as a follow-up, not as completed work.
2. **Navigation regressions:** red-first coverage explicitly includes D1 stale history destination after Back then a new Link, D2 same-URL replacement loses depth, D3 loses the guard marker, D4 unmanaged skip fragment traversal, D5 query-only loading cover, redirected Back and unchanged query push.
3. **History mechanism:** use a bounded, idempotent history tracker owned by the shell. Next captures patched methods; cleanup makes captured wrappers pass through and restores only methods still owned by the tracker. Same-URL replace keeps application metadata (depth, guard marker and owned catalogue/pagination state) while accepting Next's updated router tree. Metadata-only writes with no URL can deliberately remove markers. Cover StrictMode, remount, guard buffer depth and retained Next wrapper references. No payload/cache/account data belongs in this tracker.
4. **Single guard owner:** the shell owns one buffer, one browser listener set and one prompt. Draft entries live in a synchronous ref mirrored to state for UI. `useNavigationDraft(entry)` returns `requestTransition` and `settle(then?)`; settle synchronously cleans that entry and continues only after the buffer traversal. If other drafts remain, normal guarding still applies. Offer Save only for exactly one dirty saveable entry with no other dirty entry; pending blocks leaving/discarding. Keep editing stays possible. Save failure retains data. Storage and existing HR adapters register with this owner. No hook-local fallback owner: without a provider, actions pass through and dirty registration warns once in development; migrate standalone guard tests to a real provider.
5. **Bridge and success ordering:** keep the existing `@/lib/navigationGuard` import seam and replace its implementation with a single-owner bridge, exporting `isGuardTraversal` and `onNavigationIntent`. Sensitive payslip cleanup moves to the latter, fired only for permitted navigation. `useDraftGuard` may return the new settle control while existing void callers remain compatible. HR Period create uses settle after SAVED; scan completion uses it where navigation occurs. Owner-observed unexpected history writes must invalidate stale removal state rather than consume a future real Back. No timeout synchronization.
6. **HR Back scope:** restore Back on every HR feature header currently hiding it (16 screens: 15 literal exclusions and the conditional employee payslips header), except auth/sign-in. Existing history always uses actual Back. For direct opens, choose an authorized HR parent or first visible HR destination other than the current page; hide Back only if there is no reachable alternative. Never use `/` as the fallback for an HR-only member. Tests include HR-only direct-open and loading states. Reuse the existing HR query-state adapter via OutcomeGate rather than introducing another gate.
7. **URL state:** Codex owns a typed shared catalogue hook with codecs, current-snapshot reads, scope fallback reset and existing storage/query formats. Both catalogues plus workspace/floor readers consume a common committed-query subscription filtered by `isGuardTraversal`. Keep the typing window and cursor pagination semantics. Codex owns history.ts, Kiro owns appHistory.ts; agree the traversal signal before implementation.
8. **Writes:** Codex's independent production-hook audit confirmed stale FG success and HR/Clock A → B → A stale receipts. Extract `useOperationLifecycle(scope)` with generation/lifetime-aware tickets and per-intent duplicate acquisition; use it in the existing domain hooks. `useAsyncOperation.run(action, onSuccess?)` takes a synchronous completion callback that runs only for a current result after release. Kiro migrates post-await UI/draft/navigation effects inside FG actions into that callback. Preserve HR outcomes, exact pinned uncertain retry, scalar session IDs and strict clock-only durable recovery. Extract identity allocation only if two adapters delete actual duplicate logic; persistence formats stay domain-owned.
9. **Scope/persistence:** existing FG payload/request scopes usually append globally unique warehouse/record IDs. Do not change actor-only legacy draft keys without a demonstrated collision; dropping existing drafts is outside this PR. Workspace selection routes through the shared guard. Backend reuse remains an audit report: no schema, envelope or idempotency rewrite.
