## คำตัดสิน

**ต้องปรับแผนก่อนเริ่ม implementation** แต่ไม่ต้องเขียนใหม่ทั้งฉบับ การตีความภาพส่วนใหญ่ถูกต้อง ปัญหาอยู่ที่ข้อสมมติเกี่ยวกับพฤติกรรมของโค้ดซึ่งผิดอยู่ 3 จุด ถ้าทำตามแผนเดิม workflow ที่ต้องรักษาไว้จะเสีย:

1. UX-02/05: แถบเปิดรายละเอียดซ้ำใช้บน desktop ด้วย ส่วนปุ่ม X ในเนื้อหาคือ “ยกเลิกการเลือก” ไม่ได้ซ้ำกับปุ่มปิด sheet นอกจากนี้ การแตะพื้นที่ (area) ที่เลือกอยู่ซ้ำจะยกเลิกการเลือกและ reset กล้อง ไม่ได้เปิดรายละเอียดอีกครั้ง
2. UX-03: ขนาด `2.80 × 8.98 ม.` เป็นส่วนหนึ่งของ `label` ที่บันทึกไว้ในข้อมูล โค้ดไม่ได้นำขนาดมาต่อท้าย จึงแก้ด้วยการเปลี่ยน UI อย่างเดียวไม่ได้
3. UX-14: decoder อ่านทั้งเฟรมวิดีโอ กรอบสแกนเป็นเพียงภาพนำสายตา แผนเขียนว่าต้องให้ “กรอบสแกนตรงกับตำแหน่งที่ decoder อ่าน” ซึ่งอิงข้อสมมติที่ไม่ตรงกับโค้ด

ก่อนเริ่มงานต้องเทียบกับเวอร์ชันที่ใช้ถ่ายภาพจริง เพราะหลายหน้าในภาพไม่ตรงกับ worktree นี้ (ดู F10) ข้อที่พร้อมเริ่มหลังปรับถ้อยคำเล็กน้อยคือ UX-01, UX-09, UX-10, UX-11 และ UX-13

## Findings ตามลำดับความสำคัญ

### F1 — สูง — UX-02, UX-05: ความหมายของการปิดกับการยกเลิกการเลือกในแผนไม่ตรงโค้ด

- หลักฐาน:
  - ปุ่ม X ในเนื้อหามีชื่อ `mapClearSelection` (“ยกเลิกการเลือก”, `messages/th.json:584`) และเรียก `clearSelection` ([FloorMap.tsx:361](../../../src/components/storageLayouts/FloorMap.tsx), ฟังก์ชันอยู่ที่ :271–277)
  - ปุ่มปิด sheet ทำแค่ `setSheetSelection(undefined)` และยังคงการเลือกไว้ (:954–959)
  - แถบ `reopenDetails` แสดงทั้งกรณี `compactInspector && !sheetOpen` และกรณี desktop ที่ซ่อน inspector (`!inspectorVisible && !compactInspector`) (:926–942) โดยมี test ฝั่ง desktop ที่ [FloorMap.workspace.test.tsx:70–99](../../../src/components/storageLayouts/FloorMap.workspace.test.tsx)
  - `selectMapLocation` เปิด sheet อีกครั้งเมื่อแตะ location เดิมเฉพาะกรณี `mobile` คือหน้าจอ ≤580px (:305–316, [useStorageLayoutMobile.ts:5](../../../src/components/storageLayouts/useStorageLayoutMobile.ts)) แต่ `compactInspector` ครอบคลุมความกว้าง workspace <851px ([useFloorWorkspaceView.ts:70–73](../../../src/components/storageLayouts/useFloorWorkspaceView.ts))
  - `selectArea` เมื่อแตะ area เดิมจะเรียก `clearSelection()` แล้ว `fit()` ทุกขนาดจอ (:317–331) ภาพ IMG-01 เป็นกรณี area
- ผลถ้าทำตามแผนเดิม:
  - ลบแถบทั้งหมด: desktop ที่ซ่อนรายละเอียดแล้วเปิดกลับไม่ได้
  - บนมือถือหลังปิด sheet ของ area: แตะซ้ำแล้วกลายเป็นยกเลิกการเลือก กล้อง reset ผู้ใช้ไม่ได้กลับไปที่ “ตำแหน่งเดิม” ตามเกณฑ์ UX-02/05
  - ความกว้าง 581–850px: แตะ location ซ้ำแล้วยกเลิกการเลือก
- โค้ดมีแนวทางเดิมให้ยึดอยู่แล้ว: [StorageZonesPanel.tsx:1044–1055](../../../src/features/storageLayouts/StorageZonesPanel.tsx) ซ่อนปุ่ม “ยกเลิกการเลือก” ของ location เมื่อ `mobile`
- แก้แผน:
  - จำกัด UX-02 และ UX-05 ไว้ที่ `mobile`
  - บน `mobile` การแตะ area ที่เลือกอยู่ต้องเปิด sheet อีกครั้งแบบเดียวกับ location ไม่ใช่ `clearSelection` + `fit`
  - คงแถบไว้ใน desktop กรณี inspector ถูกซ่อน
  - เขียนในแผนให้ชัดว่าปุ่มปิด sheet ยังคงการเลือกไว้ และบนมือถือไม่มีปุ่มยกเลิกการเลือกใน sheet ซึ่งตรงกับพฤติกรรมเดิมของ location
- ตัดสินจากหลักฐานได้สำหรับ ≤580px ส่วนช่วง 581–850px ให้คงแถบไว้เป็นค่าเริ่มต้น หรือขยายการแตะเพื่อเปิดซ้ำไปถึง `compactInspector` ข้อหลังเป็นการเลือก scope (ดูข้อตัดสินใจ D4)

### F2 — สูง — UX-03 (และ UX-04): ขนาดอยู่ในชื่อพื้นที่ที่บันทึกไว้ ไม่ได้ถูกต่อด้วยโค้ด

- หลักฐาน:
  - `SheetDescription` แสดงเพียง `selectedArea.label · ชั้น` ([FloorMap.tsx:996–999](../../../src/components/storageLayouts/FloorMap.tsx))
  - หัวข้อ h3 คือ `selectedArea.label` (:357–360)
  - แถบใน IMG-01 คือ `label · รายละเอียดจุดจัดเก็บ` (:939)
  - ทั้งสามจุดแสดง `2.80 × 8.98 ม.` เหมือนกัน ขณะที่ formatter ของระบบแสดงเป็น `2.8 × 8.98 m` (IMG-02 แถว :369) ข้อความชุดแรกจึงไม่ได้มาจาก `format.dimensions`
  - label เป็นค่าที่ผู้ใช้กรอกในตัวแก้พื้นที่สงวน ([StorageLayoutScreens.tsx:2612, 2737](../../../src/features/storageLayouts/StorageLayoutScreens.tsx)) ไม่พบข้อความนี้ใน seed
- ผล: การซ่อน h3 (UX-04) ทำได้ แต่ขนาดจะยังอยู่ในคำอธิบาย ส่วนการตัดตัวเลขออกจากชื่อ แผนเองก็ห้ามไว้แล้ว และถูกต้องที่ห้าม
- แก้แผน: เปลี่ยนสถานะ UX-03 จาก “ระบุชัดจากภาพ” เป็น “ต้องแก้ข้อมูลชื่อพื้นที่” ทางที่ปลอดภัยคือผู้ใช้เปลี่ยนชื่อพื้นที่ผ่านตัวแก้พื้นที่สงวนที่มีอยู่ ไม่ต้องแก้โค้ด และไม่ใช้ production repair script ตาม README หลัก ส่วน UX-04 ซ่อน h3 เฉพาะใน sheet เพราะ `inspectorDetails` ใช้ร่วมกับ desktop aside (:922) และรายละเอียดในตาราง (:891)
- ต้องให้ผู้ใช้ตัดสินใจ (D1)

### F3 — สูง — UX-08: การเอาข้อความแจ้งความเป็นส่วนตัวออกขัดกับข้อกำหนดที่บันทึกไว้

- หลักฐาน:
  - [SearchDialog.tsx:258–268](../../../src/components/shell/search/SearchDialog.tsx) มี comment ว่า “Said before anything is sent”
  - [hr-ui-simplification-claude-codex-2026-10-10.md:41, 45](../hr-ui-simplification-claude-codex-2026-10-10.md) กำหนดว่า “Keep a truthful one-line disclosure visible before asking AI”
  - test ที่ตรวจข้อความนี้: `GlobalSearch.test.tsx:261–303`, `SearchDialogLoader.test.tsx:267`
- ผล: การวงแดงชัดเจน แต่ถ้าเอาออกตามนั้น ผู้ใช้จะไม่เห็นคำเตือนใดก่อนส่งข้อความ (ซึ่งอาจมีชื่อคน) ให้ AI provider `AiPanel` มีแค่ตัวอย่างคำถามกับ context (:515–560)
- แก้แผน: เพิ่มใน UX-08 ว่าข้อนี้แทนที่ข้อกำหนดเดิม และต้องบันทึกการตัดสินใจไว้ ทางเลือกมีสองแบบ คือเอาออกตามภาพ หรือแสดงเฉพาะเมื่อเข้าโหมด AI/ก่อนส่งครั้งแรก แผนไม่ควรเลือกแทนผู้ใช้
- ต้องให้ผู้ใช้ตัดสินใจ (D2)

### F4 — สูง — UX-14: กรอบสแกนไม่ใช่พื้นที่ที่ decoder อ่าน

- หลักฐาน:
  - กรอบสแกนใน [BarcodeCameraBox.tsx:135–139](../../../src/features/finishedGoods/BarcodeCameraBox.tsx) เป็น `aria-hidden` และ `pointer-events-none`
  - ZXing `decodeFromStream` อ่านทั้ง stream และ fallback วาดทั้งเฟรมลง canvas ([useBarcodeCamera.ts:121–132, 146–148](../../../src/features/finishedGoods/useBarcodeCamera.ts))
  - container ใช้ `aspectRatio: videoAspect` คู่กับ `object-contain` (:124, :133) เฟรมทั้งหมดจึงมองเห็นอยู่แล้ว ข้อจำกัดจริงคือ `maxWidth: 320 * videoAspect` เท่านั้น
- ผล: ถ้าเปลี่ยนเป็น `object-cover` ส่วนที่ถูก crop ยังถูกอ่านอยู่ จึงอาจรับป้ายตำแหน่งที่ผู้ใช้มองไม่เห็นบนจอ ซึ่งอันตรายในจุดที่มีป้ายหลายอันติดกัน
- แก้เกณฑ์ UX-14: “เฟรมที่ decoder อ่านต้องมองเห็นได้ทั้งหมด คง `object-contain` และ container ที่สัดส่วนตรงกับวิดีโอ ขยายโดยเพิ่มเพดานความกว้าง/ความสูง (เช่นอิง `dvh`) ห้าม crop ภาพโดยไม่จำกัดพื้นที่ decode ให้ตรงกัน”
- ข้อสังเกตเรื่องเวอร์ชัน: ใน IMG-08 preview กว้างประมาณ 66% ของภาพ (412/628 px, สัดส่วนราว 0.56) แต่สูตรในฐานโค้ดให้ความกว้างสูงสุด 180 CSS px ซึ่งเท่ากับ 42–50% ของจอ 360–430px ภาพจึงน่าจะมาจากเวอร์ชันที่เพดานต่างออกไป
- ตัดสินจากหลักฐานได้

## เกณฑ์ตรวจรับที่ควรเพิ่มหรือแก้

- ผัง (≤580px):
  - เลือก area → ปิด sheet → แตะ area เดิม: sheet เปิดอีกครั้ง zoom/pan ไม่เปลี่ยน ไม่มีแถบทับผัง
  - ใน sheet ไม่มีปุ่ม “ยกเลิกการเลือก”
- ผัง desktop: “Hide details” แล้วเปิดกลับได้ inspector ยังแสดงชื่อพื้นที่และปุ่ม X
- อาคาร: `getByRole("heading", { name: building.name })` ตรงกับชื่ออาคารเท่านั้น ปุ่ม “แก้ไขการตั้งค่าอาคาร” อยู่ต่อจากชื่อหนึ่งปุ่ม ไม่มีใน actions และซ่อนเมื่อ `dirty`/`ARCHIVED`
- รายการอาคาร: มีปุ่มเพิ่มอาคารเพียงปุ่มเดียวในแต่ละมุมมอง (cards/table) ปุ่มล้างคำค้นไม่ทับปุ่มเพิ่มอาคารที่ 360px ทั้งไทยและอังกฤษ
- Search: ค่า `getBoundingClientRect()` ของ title กับ close มี center-y ต่างกันไม่เกิน 1px และ dialog อื่นไม่เปลี่ยน
- กล้อง LOCATION: ทั้งเฟรมวิดีโอมองเห็นได้ ไม่มีการ crop preview ส่วนหน้าสแกนอื่นไม่เปลี่ยน ถ้า D5 = เฉพาะหน้านี้
- AI reader: ขณะ busy ไม่มี action อ่านซ้ำ กดหนึ่งครั้งเรียก `extract` หนึ่งครั้ง การแตะภาพทั่วไปไม่เรียก AI

## ข้อตัดสินใจที่เหลือ

- D1 (UX-03): เปลี่ยนชื่อพื้นที่ “พื้นที่จัดเตรียมสินค้า · 1 · 2.80 × 8.98 ม.” ในข้อมูล หรือยอมให้ขนาดยังอยู่ในชื่อ
- D2 (UX-08): เอาข้อความแจ้ง AI ออกทั้งหมดตามภาพ ซึ่งแทนที่ข้อกำหนดเดิม หรือแสดงเฉพาะเมื่อเข้าโหมด AI
- D3 (UX-16/17): ลูกศรกลางภาพหมายถึงอ่านซ้ำ หมุนภาพ หรือถ่ายใหม่ และไอคอน ↺ ด้านล่างในเวอร์ชันจริงทำอะไร
- D4 (UX-02/05): ช่วง 581–850px คงแถบไว้ (ค่าเริ่มต้น) หรือใช้การแตะเพื่อเปิดซ้ำเหมือนมือถือ
- D5 (UX-14/15): ปรับเฉพาะหน้าสแกนตำแหน่ง (ค่าเริ่มต้น) หรือทุกหน้าที่ใช้ `BarcodeCameraBox` และกล้อง AI
- D6 (UX-12): ตำแหน่งปุ่มเพิ่มอาคารในมุมมอง “ทุกตำแหน่ง”

UX-01 และ UX-10 ยืนยันแล้ว รายงานนี้ไม่ได้เปิดคำถามสองข้อนั้นใหม่

## ข้อจำกัด

- ตรวจภาพแบบ static เท่านั้น ไม่ได้เปิดแอป ไม่ได้รัน test และไม่ได้วัด CSS px จริง ค่าระยะในภาพเป็นการประมาณจากพิกเซลของไฟล์
- ไม่มี source ของหน้า AI usage, หน้าสแกน “เราอยู่ที่ไหน?” และ sidebar แบบกลุ่ม ใน worktree นี้ ข้อสรุปเกี่ยวกับหน้าเหล่านั้นจึงอิงภาพและ component ฐานเท่านั้น
- ไม่ได้ค้น checkout อื่น และไม่ได้ตรวจ SHA-256 ของภาพซ้ำ
