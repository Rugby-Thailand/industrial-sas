# S03 — Employee list, profile and offboarding

> Historical research baseline: “What we have today” and task IDs below describe the pre-implementation investigation, not current coverage. Current behavior and limitations are maintained in `docs/operations/hr-foundation.md`.

## Summary

HRZoft's employee module opens on a `พนักงาน` list (sub-tabs `พนักงาน` / `ตารางการทำงาน` / `หนังสือเตือน` / `ขอเข้าร่วมบริษัท`) with a 12-column MUI DataGrid, a search box, a `การแสดงผล` column picker, a `กรอง` filter whose default is employment-status `ทำงานอยู่`, a `ซ่อนจำนวนเงิน` toggle, a card/table view switch and pagination. Each row opens a profile at `/core/employee/<id>` with **15 tabs**; this slice owns the list UX, the tab structure and the personal / contact (incl. emergency contact) / salary-bank / documents tabs, plus probation and employment-status transitions and offboarding.
This run reached the authenticated admin demo and directly read the list, the personal / contact / salary / documents / employment tabs and the toolbar; it did not open the add-employee form (same editor as the profile) and found no employee Excel-import screen.
Our app has a minimal employee: code, displayName, site, linked account, supervisor, start/end dates, weekly schedule and `status` ACTIVE/INACTIVE — no personal info, no contact/emergency, no bank account, no documents, no probation, no profile tabs, no employment-status filter, no bulk actions and no Excel import.
Biggest gaps: a tabbed employee profile; personal/contact/emergency/bank/documents data; probation (`วันที่บรรจุ`) and employment-status transitions with an effective-change history; and offboarding (status → last day `วันสิ้นสุดสัญญา`) that drops the person from the active list.
Slice 01 owns the employment-tab setup fields (department/position/level/supervisor/branch/workplace/employment type); this slice references them only for transitions, not CRUD.
Counts: **17 seen, 6 guess, 2 unknown; 25 tasks.**

## What we have today

Read boundaries: `convex/schema.ts` (`hrEmployees`, line 133), `convex/hr/setup.ts` (`saveEmployee`, `employeesPage`), `convex/model/hr/employee.ts` (`validateEmployeeDraft`), `convex/model/hr/csv.ts`, `src/features/hr/EmployeeForm.tsx`, `EmployeesScreen.tsx`; context map `docs/plans/hr-core-flow-2026-10-18/index.html` NODES `emp`, `offboard`.

- `hrEmployees` stores `warehouseId` (site), `code` (regex `^[A-Z0-9][A-Z0-9._-]{0,31}$`, upper-cased), `displayName`, optional `userId`, `supervisorUserId`, reviewer/excluded-reviewer lists, `employmentStartDate`, optional `employmentEndDate`, `status` (`ACTIVE`/`INACTIVE`), optional weekly `schedule`, audit/version fields. There is **no** personal info, contact, emergency contact, bank account, documents, department, position, probation or employment-type field.
- `EmployeesScreen.tsx` renders a list with columns Employee (name+code+siteCode), Account, Supervisor, Schedule, Status, actions; filters are search (`q`), site and status (ACTIVE/INACTIVE). It has an Add button (`hr-employee-add`) and card+table layouts — but **no** employment-status tabs, **no** bulk actions and **no** Excel import.
- `EmployeeForm.tsx` edits code, displayName, site, status, linked account, supervisor, start/end dates and schedule, with an `EmployeeHistory` audit panel. It is a single form, not a tabbed profile.
- `saveEmployee` validates draft/schedule/site-scope/code-uniqueness, one-employee-per-account and an active supervisor; `validateEmployeeDraft` checks code, name ≤120, ISO dates and end≥start (codes `EMPLOYEE_CODE_INVALID`, `EMPLOYEE_NAME_INVALID`, `EMPLOYMENT_DATE_INVALID`, `EMPLOYMENT_RANGE_INVALID`, `SELF_SUPERVISOR`). There is **no** Excel-import mutation and **no** offboarding flow — only `status = INACTIVE` + an optional `employmentEndDate`. `convex/model/hr/csv.ts` is attendance-export only, not employee import.

## UX notes (proposed for our app; Thai labels are HRZoft's observed copy)

- **List** (`/en/hr/employees`): keep our search + site + status filters, but add an employment-status filter whose default is **Active** (`ทำงานอยู่`) so offboarded people are hidden by default, a column-display picker, a hide-amounts toggle, and a card/table switch. HRZoft's 12 columns map onto future fields; our list only has Employee/Account/Supervisor/Schedule/Status today. Module sub-tabs (`ตารางการทำงาน` schedule = slice 04, `หนังสือเตือน` warnings, `ขอเข้าร่วมบริษัท` join requests) are navigation only here.
- **Profile** (`/en/hr/employees/:id`): a tabbed page. This slice owns Personal, Contact (incl. emergency contact), Salary-tab **presence** with the bank-account block, and Documents. Group personal fields as identity / demographics / note; contact as email+phone+Line / address / emergency contact; bank as `ธนาคาร`/`เลขที่บัญชี`/`ชื่อบัญชีธนาคาร`/`รหัสสาขา` with a cash/bank pay-type switch. Use readable English labels (Title, First/Last name, National ID, Date of birth, Nationality, Marital status, Emergency contact name/relationship, Bank, Account number, …).
- **Transitions**: probation confirmation is a dated event (`วันที่บรรจุ`) that flips the list `สถานะ` from Probation to confirmed; employment-status changes keep an **effective-dated history** (`ประวัติการเปลี่ยนแปลง (มีผล)`) rather than overwriting. Model status as an enum richer than ACTIVE/INACTIVE (at least Probation / Active / Resigned / Terminated).
- **Offboarding**: a terminal status + last working day (`วันสิ้นสุดสัญญา`) with a resignation/termination reason; on save the person leaves the default Active list (keep the record for history, mirroring our existing status filter), and final leave balances are settled on the `โควต้าวันลา` tab. Whether a terminal status also disables the linked login is unverified (S03-23).
- **Empty states**: propose `No documents yet`, `No emergency contact yet` rather than blank panels; not separately tested.
- **Labels owned elsewhere**: the employment-tab masters (department/position/level/supervisor/branch/workplace/employment type) and `บทบาท` role are slice 01/02; payroll maths and payslip are slice 08; schedule tab is slice 04.
