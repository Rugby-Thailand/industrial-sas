### F1 — Medium — declared 1550-cell roster save exceeds Convex's 4096 index-range limit (RED repro)

- `convex/model/hr/roster.ts:55` `MAX_ROSTER_CELLS = 1550` ("50 employees × 31 days fits"), validated at `convex/hr/roster.ts:454`.
- `convex/hr/roster.ts:498-545` performs ≥3 indexed reads per cell (attendance `.first()` 517-526, `hasFrozenPlan` 530 → `convex/hr/shared.ts` `hasFrozenPlan`, assignment `.unique()` 532-541) plus employee gets and hrCommand reads ⇒ ~4,700 ranges at the bound; the effective ceiling is roughly 1,300 cells.
- Repro: `docs/plans/hr-parity/overnight-evidence/repro/04-shifts-roster-limits.test.ts.txt` (copy to `tests/integration/hr-parity/04-shifts-roster-limits.test.ts`, run with `--maxWorkers=2`). It enables convex-test `transactionLimits` (deployed limits), seeds 50 employees via registered `saveEmployee`, reads the registered roster (passes: 50 rows), then saves OFF to all 1550 returned cells. Result: `ConvexError INTERNAL_ERROR`; underlying (temporarily logged, reverted): `Too many index ranges read in a single function execution (limit: 4096)`.
- Effect: a large legitimate selection fails as an opaque internal error, no partial write (transaction aborts). Existing suite never runs with limits on. Fix options (coordinator): lower bound to what fits with margin and refuse with `ROSTER_SELECTION_INVALID`, or batch the per-cell reads by employee range (one attendance range, one period-row range, one assignment range per employee).
- UI makes this reachable only by ~1,300+ individual clicks (no select-all), hence Medium not High.

### F3 — Medium — PLAUSIBLE (code-path, not executed) — roster edits are not refused over pending/approved leave claims; leave approval later overwrites the roster plan

- Roster refusal set (`convex/hr/roster.ts:517-531`) covers attendance day, CLOSED period, ever-frozen rows, not `hrLeaveDayClaims`.
- Leave submission snapshots `livePlan` per date (`convex/hr/leave.ts:480-507`) and counts SCHEDULED dates for balance; approval (`leave.ts:1041-1050`) creates the day via `ensureDay` and patches `plan` to the submission-time snapshot. A roster OFF set between submit and approve is therefore silently replaced by the old SCHEDULED plan with LEAVE disposition and the reserved balance still includes that date; conversely a SHIFT assigned onto an originally-OFF date inside a leave range is unclaimed.
- Spec S04-22 leaves leave/OFF precedence unknown and the evidence defers leave overlays; the conservative policy should either refuse roster changes on claimed dates or document this precedence. Not reproduced because leave setup (policy/accounts/preview hash) exceeded the time box.

`convex/model/hr/roster.ts:52-53` `MAX_SITE_SHIFTS = 99`; `convex/hr/roster.ts:184-187` refuses create when 99 exist. `shifts-roster.md` states "supports 100 definitions per site".
