## Current delivery status — 12 October 2026

The [final execution plan](ui-hr-final-execution-2026-10-12.md) supersedes the earlier delivery status below. The final branch implements policy drafts/activation, reconciled leave accounts and audited request lifecycle, request history filters, employee frozen-period reads/export, independent home updates, saved shortcuts, audience-restricted immediate/scheduled announcements and receipts, notifications, and private staged/published payslips. Charge preview and returned-request resubmission preserve financial versions; deliberate payslip exclusions retain source-row reasons. These additions are being checked as one release, not activated for a production company.

Payslips use a deliberately narrow canonical CSV (`employee_code,period_from,period_to,payment_date,gross,deductions,net`) and original PDFs named by employee code, with at most 20 source rows and 384 KiB per included PDF. Invalid included rows block publication; an explicit excluded source row needs a recorded reason. The original CSV, included set, file hashes and immutable replacement history are retained. No payroll engine or PDF/OCR extraction is claimed.

Original PDF bytes are held in private tenant records for this bounded import format. There is no publicly reusable file URL. Audited reveal/download mutations check current linked ownership, current policy, signed provider freshness and session-bound expiry. Default verification is 5 minutes (supported 2–15; quantized provider ages are handled conservatively), with download tickets at most 60 seconds. Missing provider claims or operator capability configuration leaves sensitive access unavailable.

Operators must verify the real Clerk Convex JWT contains signed `fva`, `iat` and `sid` claims before setting `HR_PAYSLIP_PROVIDER_FRESHNESS_ENABLED=true`. `HR_PAYSLIP_PRIVATE_STORAGE_ENABLED=true` confirms the private bounded-record delivery model is suitable for the deployment. Both capabilities are off by default and HR cannot replace them with a local checkbox. Decide actual payroll provenance, publication owners and retention before enabling the company policy; no automatic retention deletion or production capability change occurs in this code delivery.

Backend additive schema/functions must deploy before the corresponding UI. Existing attendance remains independent of activation. HR reviews calendar, reviewer coverage, existing higher benefits and verified opening usage before activating leave; balances are never populated from the synthetic preview. Announcement jobs recheck the saved publisher’s current company membership, permissions, audience scope and active policy when due. Replacing content uses a new unread publication instead of overwriting employee receipts.

Actual verification and merge/release results are recorded in `docs/reviews/ui-hr-final-2026-10-12/` and the final plan. The paragraphs below retain the original engineering checklist as historical planning context.

## B follow-through: attendance periods and complete request searching

1. Add an employee period query in a dedicated `convex/hr/selfPeriods.ts`. Resolve organization and linked employee on the server; accept a bounded period cursor, not another employee/site ID. Return only site periods relevant to the employee's employment dates. Specify which revision is current and whether the period is open or closed.
2. For closed period summaries, load the selected frozen period version and its employee rows. Do not aggregate live attendance and label it frozen. Return version ID, revision, closure date, completeness and derived totals together. Add an employee-owned period detail query checking period site and row employee before serialization.
3. Adapt `HistoryScreen` with the shared month/period selector. Current month remains live; closed periods show the frozen revision and dates. Switching scope resets incompatible filters. Link summary counts to the same loaded row IDs; no count can refer to hidden future dates.
4. Define late/early thresholds before adding their metrics. Define break and overnight interpretation explicitly. Outside-shift minutes remain outside-shift minutes until approved OT is a delivered workflow.
5. Add a server request search contract only after choosing bounded search behavior. Keep correction status/type predicates in indexed access; avoid returning a loaded-page search as global search. Preserve old exact request IDs, returned reasons and retained histories.
6. Add employee CSV export for attendance only from a complete bounded live range or authorized frozen version. Include the scope, revision and original/effective distinction. Local preview CSV is not a production source.

Acceptance: live/frozen totals reconcile to exact rows; current/future and overnight date boundaries pass; other employee/site/period IDs fail; draft correction navigation protections remain; current `PENDING`, `CERTIFIED`, `RETURNED` semantics remain.

## C policy gates and concrete delivery units

User direction now supplies the starting policy: prefill a [Thailand legal-minimum preset and suggested company settings](thailand-hr-policy-defaults-2026-10-11.md), allow HR configuration, and retain explicit activation gates. Implement preset/settings/validation infrastructure without waiting for HR to invent every rule. HR reviews coverage, existing benefits, actual calendars, opening balances and routing, then activates an effective version before employee writes are enabled. The screenshot quotas and the earlier illustrative 12-day allocation are not the default.

The configuration contract must record the following decisions with a responsible company owner and effective date. Values are prefilled wherever the Thailand preset defines them; company-specific evidence is still required for activation:

| Decision                 | Required information                                                                           | What this controls                                           |
| ------------------------ | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Types and eligibility    | Type codes, covered employment categories/sites, waiting periods                               | Controls which types an employee may request.                |
| Entitlement              | Grant/accrual, proration, year basis, units and precision                                      | Determines allocations and charge arithmetic.                |
| Carryover/expiry         | Caps, expiry date, consumption order and transition rules                                      | Determines balances and historical ledger events.            |
| Charging calendar        | Working-day/calendar-day basis, employee schedule, holidays, timezone, overnight business date | Determines exact charged dates and intervals.                |
| Partial day/evidence     | Half-day/time interval rules, minimum charge, evidence thresholds                              | Determines form choices and attendance integration.          |
| Availability and overlap | Reservation timing, overdraft rules, overlap with other requests/manual HR leave               | Prevents overspending and duplicate usage.                   |
| Decisions                | Approver scope/delegation, denial, return, employee cancellation, approved cancellation        | Determines state transitions and authorization.              |
| Historical changes       | Closed period adjustments, cross-year split, policy-version transitions                        | Determines which data is frozen and how changes are audited. |

Deliver in the following order; every unit includes both locales and authorized loading/empty/error states:

1. **Preset, configuration and pure policy calculator.** Implement the linked Thailand preset, separate legal floors from suggested operational settings, and add HR Save draft/Activate controls. Validate floors on the server; model leave entitlement separately from employer-paid caps. Add `convex/model/hr/leave.ts` for eligibility, effective policy selection, charge-day snapshots and cross-year splitting. All inputs are explicit policy/schedule/holiday evidence. Add tables for immutable policy versions and employee allocations, with organization/type/effective-date and organization/employee/year indexes. Saving a future version must retain the form's persisted values, and editing an effective version creates a new version. Draft versions cannot authorize employee writes.
2. **Ledger and balance query.** Add immutable ledger events for grant/accrual/carryover/reserve/release/consume/approved adjustment. Index by organization/employee/type/year plus a unique operation key enforced transactionally. Store units as integer smallest policy units, not floating-point counter arithmetic. Derive entitled, used, reserved and available consistently. Historical event corrections use compensating events.
3. **Employee submit and charge preview.** Add `leave.previewCharge({type,dates,unit})`, `leave.submit({operationId,...})`, employee request list/detail and balance query. Server resolves identity, validates employment/eligibility, selects immutable policy/schedule/holiday snapshots, rejects invalid/overlapping charge intervals, then writes request and reservation atomically. An uncertain response retries the same operation ID; it never produces a second reservation.
4. **Leave UI.** Add `LeaveScreen`, type/balance summary, request form and exact detail. Reuse `HrActionCard`, `SelectControl`, `FormField`, existing draft guard, `useHrWrite` and status components. Keep leave-specific calculation visible near dates; no generic correction form hides type/evidence rules. Add the route to the fixed shortcut allowlist only when its backend is functional.
5. **Supervisor review.** Add a distinct leave queue and decision API with direct-report/site checks and self-review denial. Review shows charge snapshots, entitlement/reservation evidence, proposed dates and prior decisions. Approval converts reservation into consumption in the same transaction; return releases the reservation; resubmit revalidates and appends history. Denial and cancellation behavior must follow the recorded company decision rather than copied correction states.
6. **Attendance and period integration.** Link full-day approved leave to the existing `LEAVE` disposition only through audited request references. Implement partial intervals after their model is defined. Reconcile manual HR dispositions against linked leave so no date is charged twice. Integrate unresolved leave into period closure under confirmed rules. Approved changes in a closed period go through its revision path.
7. **Migration and rollout.** Configure the first real policy version and allocation importer after HR verifies source balances. Do not infer balances from preview examples or unrelated historical `LEAVE` dispositions. Gate routes by deployed capability, rehearse company-owner acceptance, and reconcile first ledger totals against the approved source.

Acceptance: concurrent submissions cannot overspend; retried submit/decision cannot reserve/consume twice; charge preview equals persisted snapshot; nonworking/holiday/half-day/overnight/cross-year examples follow real policy; unauthorized/self review fails; retained return/resubmit history remains; manual leave does not double charge; closed periods remain immutable; effective historical policy changes cannot rewrite old charges.

## D announcements, notifications and preferences

Start with the linked preset's recommended company settings: HR publishers, an explicit current-organization audience, optional authorized site/group targeting, Asia/Bangkok scheduling, ordinary read receipts and acknowledgment off. These are editable product recommendations, not Thai legal minimums. HR reviews and activates publication settings before publishing. Retention remains a company-specific decision.

1. Add announcement draft/publication/version tables, explicit audience snapshots and employee/version read receipts. Index published audience/time queries and receipt employee/version keys. Keep draft and scheduled future versions out of employee queries.
2. Implement HR draft/load/save/publish APIs under explicit publisher permission and existing tenant authorization. Publication uses one operation ID, captures version/audience/time, records audit evidence and creates durable publication events. A stale editor cannot overwrite a newer version without seeing a conflict.
3. Add employee feed/detail APIs resolving the linked employee and audience server-side. Re-check the audience when opening a detail ID. Read mutations store employee/version receipts; ordinary reading does not imply policy acknowledgment.
4. Implement feed/detail UI with real author/time/version, readable multiline content, explicit pinned order and retained unread status. Reuse existing panels, statuses, fields and draft guards. Add a separate acknowledgment action only when that requirement is confirmed.
5. Add durable notification events and a per-employee inbox. Decision/publication transactions emit deduplicated events, with employee/org keys and authorized destination descriptors. Worker retries cannot duplicate a notice. Queries expose cursor pages/unread counts; mark-one/mark-all mutate only the linked employee's notices.
6. Notification destination resolution uses the existing navigation registry and rechecks target access. A revoked destination reports unavailable rather than exposing record details. Notification logs carry event IDs and outcomes, not sensitive payloads.
7. Preferences use per-user/per-organization storage, revision conflict checks and a fixed allowlist of delivered routes. Clocking remains outside customization. Mouse/touch and keyboard reorder share one drag handle; Save/Cancel and reload preserve state. This task is integrating this independent preference unit separately.

Acceptance: no draft/future/audience leak; version/read rules hold; unread count and pages reconcile; event retries never duplicate notices; access revocation blocks target data; preference records never cross users/orgs; unsupported route IDs are rejected; pending saves and dirty navigation preserve existing guards.

## E imported payslips and protected document viewing

Use the linked preset's recommended settings: own published statements only, fresh provider verification for reveal/download with a five-minute server-enforced validity window, private short-lived download delivery and explicit immutable publication/replacement versions. HR may configure supported durations. These are privacy/product recommendations, not statutory Thai verification periods. Activation still requires the actual payroll source format, exact employee mapping identifier, import/publication owners, source provenance, verified provider/storage capability and recorded document retention.

1. Verify the actual provider capability before choosing account verification. Define a server-verifiable fresh-auth claim and expiration contract. Do not ship a local modal, CSS masking or custom PIN/password store as security.
2. Add private import-batch, source-file, validated-row and published-version models. Employee/period/version indexes and batch operation keys support complete publication. Files remain private; authorization gates storage access and generated download URLs.
3. Parse source records strictly. Treat blank money as invalid rather than zero; compute source arithmetic in integer satang; reject unknown/duplicate employee identifiers, duplicate period/version records and mismatched selected period. Reading a replacement file clears old staged rows and names any failed file.
4. Build the HR staged import screen with row-level errors and an explicit invalid/excluded state. Recording an exclusion requires its reason and publication scope. Bind every staged row to the selected period/version; changing that selection cannot silently reassign prior rows.
5. Publish one validated immutable batch through an idempotent operation ID. Preserve the original source and audit evidence. An approved replacement creates a new version under the confirmed replacement policy, and never silently overwrites an already published statement. Emit deduplicated employee notices.
6. Add employee list/metadata APIs returning only owned published period/version metadata. Add a separate sensitive detail API requiring organization, linked employee and verified fresh-auth evidence before salary line items are serialized. Never send amounts to the client merely to mask them visually.
7. Protected download rechecks the same employee and verification evidence, binds exact period/version and expires. Reveal state clears on expiry, Hide, logout, selected period change and navigation; cancelled/failed verification returns focus and leaves the selected period masked.
8. Add source/detail/document reconciliation and audit events for validation, publication, verification and download. Audit records contain identifiers and outcomes, not salary values. Define deletion/retention workers after the policy is recorded.

Acceptance: other employee/list/detail/document IDs fail server-side; expired/revoked verification blocks both reveal and download; stale imports cannot publish under a new period; retries cannot duplicate publication; invalid employee/money/duplicate rows cannot pass; document totals match published source; replacement versions are explicit; sensitive values never appear in pre-verification payloads, browser logs or audit payloads.
