Message sizes are `Buffer.byteLength(JSON.stringify(pickMessages(catalogue, namespaces)))`, which is compact JSON of each provider's namespaces before transport encoding. `src/i18n/clientMessages.ts` lists the namespaces.

**v1 scaling limit.** A filtered search pages through the index in bounded chunks: 20 rows per call at page size 20. A match near the start of a long tail is not shown until the lookahead confirms whether a next page exists. A synthetic 10,000-row organization where only the first 20 rows match needs about 500 sequential calls before page one appears, each with bounded reads. That is a request count, not a latency measurement. Customer lists are expected to stay in the hundreds. If an organization grows past a few thousand customers, return the filled page first and resolve Next separately, or add the v2 search index.

No existing query or mutation reads the customers table. Job scans and products are untouched in v1.

The real React components render in a Vite harness with mocked Convex responses (a local, untracked `output/customer-preview`): Thai and English, light and dark, 1280px and 390px. ## Reproduce

```sh
pnpm exec vitest run src/features/customers                         # caller and Back tests
pnpm exec vitest run --project integration --maxWorkers 2 --testTimeout 20000 \
  customers.integration permissions.integration hr-workflows ai-usage hr-roster-paging
pnpm check:navigation
pnpm test:e2e:hr:local tests/e2e/hr-local/customers.spec.ts         # needs the private .env.local described in tests/e2e/hr-local/README.md
```

The local real-browser runner twice stopped before any test started, because its web server did not come up. Retrying passed both times. The tests themselves never failed for this reason.
