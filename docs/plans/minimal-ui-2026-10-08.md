# Minimal UI implementation

Requested outcome: implement the approved seven-phase redesign across the planner, test and fix it in repeated audits, capture the real UI at each workflow action in desktop and mobile sizes, and open a PR. The image concepts are direction for spacing, hierarchy and palette; screenshots must come from the running application.

Baseline: `03a157aaea8e2ae64539de58ef9a85e78b309f2c` on `main`. Work takes place in a separate checkout so existing uncommitted scan work stays intact.

| Phase                        | Implementation                                                                                                                             | Expected UX and acceptance                                                                                                                                                                                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Foundation and navigation | Shared light tokens, compact spacing/type/controls, 64 px collapsed rail and 208 px expanded sidebar, closed mobile drawer                 | Content starts with the current task; the four primary destinations remain discoverable. Keyboard focus, Escape and close-on-navigation work. Mobile controls keep generous touch areas. Warehouse identity stays visible; switching is restricted to catalogue pages.                 |
| 2. Products and packing      | Desktop tables by default, flat mobile lists, compact totals, separate required details and optional references, smaller empty preview     | Full identifiers, quantities, counting units and state stay readable. Search/filter/cursor pagination and desktop layout preferences survive. Product saving and batch creation remain distinct. Copied measurements require their own check. Drafts survive failed requests.          |
| 3. Buildings and maps        | Flat building rows and editor panels, common map palette, neutral model background, smaller inspector styling                              | Floor and selected location remain clear. Location selection works as a desktop inspector and mobile sheet. Geometry, collisions, occupied locations, stale versions and draft/activation rules remain authoritative. Saving is distinct from activation.                              |
| 4. Storage operations        | Compact pallet context, optional QR/dimension details closed, common form/panel improvements                                               | Identity, quantity, units, source, target and next action stay visible. Measurement, reservation, destination verification, physical placement, move and stack retain separate steps. Existing geometry and permission guards stay intact. No new assertion of weight safety is added. |
| 5. Scan and records          | Flat ticket presentation, duplicate review, numeric validation, editable photo-failure recovery, stable request identity and pending locks | AI output remains reviewable; repeated identities require a check. Retry does not create another request identity for the same submission. Submitted values/selection cannot change while saving. Recording a ticket location does not imply stored inventory.                         |
| 6. Access and public pages   | Compact sign-in/setup/public layouts, optional setup remediation, validated post-sign-in return path                                       | Sign-in returns to the requested same-locale planner route and query. External or malformed destinations are rejected. Setup reports configuration accurately. Public information stays readable outside the authenticated shell.                                                      |
| 7. Audit and delivery        | Unit/integration/accessibility tests, real browser actions, screenshot pairs, two-axis code review, final build and PR                     | Fix issues found in tests and real screens, rerun relevant checks, retain reviewable desktop/mobile evidence, and open the PR with validation and practical limits.                                                                                                                    |

Palette: white canvas, `#F6F7F9` rail, `#17212F` text, `#475569` muted text, `#1D4ED8` primary, `#EFF6FF` selection, `#166534` success, `#92400E` warning, `#B91C1C` danger and `#808080` control borders. Existing dark mode remains supported. Status is conveyed with text and symbols as well as color.

Screenshot walkthroughs use local demo or `QA-` records and 1440 × 1000 desktop / 390 × 844 mobile CSS viewports. Each pair records a real screen state after the named action, rather than a generated design. Responsive screenshots do not simulate a physical mobile camera or software keyboard; hardware checks remain a separate validation limit.
