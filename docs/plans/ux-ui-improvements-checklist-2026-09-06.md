# แผนปรับ UX/UI และวิธีตรวจสอบ

สถานะ: Implement และตรวจตามรายการแล้ว — 7 กันยายน 2026 (Bangkok); รายละเอียดหลักฐานและข้อจำกัดอยู่ในผลตรวจด้านล่าง

ขอบเขต: FG → ชุดจัดเตรียมและแบ่งบรรจุ → วัดขนาด → เลือกตำแหน่ง → จอง → ยืนยันจัดเก็บ → ซ้อนและย้ายพาเลท รวมหน้าจัดการอาคารและจุดจัดเก็บ

## รายการปรับปรุงและวิธีตรวจ

| สิ่งที่ปรับ | แนวทางปรับ | วิธีตรวจ | เกณฑ์ผ่าน |
| --- | --- | --- | --- |
| สีและ contrast | ทำให้ข้อความรอง ขอบช่องกรอก และปุ่มอ่านชัด แยก selected, disabled และ error | วัด contrast ของสีที่แสดงจริง ตรวจปกติ, hover, focus, disabled และ error | อ่านข้อมูลสำคัญได้และแยกสถานะได้โดยไม่อาศัยสีเพียงอย่างเดียว |
| ลดขั้นตอนซ้ำ | พิจารณาเปิดให้ปรับตำแหน่งในหน้าหลัก และรวมหน้าสรุปที่แสดงข้อมูลเดิม | บันทึกเส้นทางและจำนวนคลิกก่อน–หลัง ทำงานเดียวกันด้วยข้อมูลเดียวกัน | ขั้นตอนลดลงโดยยังเห็นปลายทางและผลของการกระทำก่อนจอง |
| ปุ่มหลัก | แต่ละสถานะมีการกระทำหลักหนึ่งอย่าง เช่น จองพื้นที่ หรือยืนยันการวาง จัดงานรองให้เด่นน้อยกว่า | ตรวจทุกหน้าและทุกสถานะ รวมขณะกำลังส่งข้อมูล | รู้ว่าต้องทำอะไรต่อ ไม่มีปุ่มที่ดูเหมือนทำงานเดียวกันแต่ให้ผลต่างกัน |
| ไอคอน | ใช้ไอคอนกับงานที่คุ้นเคย พร้อม tooltip และ accessible name งานสำคัญหรือกำกวมมีข้อความสั้น | ทดสอบเมาส์ คีย์บอร์ด และมือถือที่ไม่มี hover | เข้าใจและเรียกใช้งานได้โดยไม่ต้องพึ่ง tooltip เพียงอย่างเดียว |
| ย้อนกลับและยกเลิก | ใช้รูปแบบเดียวกัน วางลิงก์ย้อนกลับซ้ายบน และแยกการย้อนหน้าจากการยกเลิกรายการ | ย้อนกลับจากทุกขั้น ใช้ browser Back เปิดผ่าน direct URL และลองมีข้อมูลที่ยังไม่บันทึก | กลับไปยังหน้าที่เกี่ยวข้อง ไม่สูญเสียข้อมูลหรือปล่อยการจองโดยไม่ตั้งใจ |
| คำเรียกและคำแนะนำ | ใช้ FG, ชุดจัดเตรียม, หน่วยจัดเก็บ, กล่อง และพาเลทให้ตรงกับข้อมูลและสิ่งที่ระบบอนุญาต | ตรวจภาษาไทย/อังกฤษกับ PALLET, BOX และ OTHER | ไม่มีคำแนะนำให้ทำสิ่งที่ชนิดหน่วยนั้นทำไม่ได้ เช่น แนะนำให้ BOX ซ้อนทั้งที่รองรับเฉพาะ PALLET |
| ภาพ 2D/3D | แสดงฐานที่เลือก ระดับ Z และเหตุผลที่วางไม่ได้ใกล้ภาพ รักษามุมกล้องระหว่างปรับตำแหน่ง | ลากขึ้นฐาน ลากออก วางเหลื่อม หมุน แก้ X/Y และใช้ปุ่มลูกศร | ภาพ พิกัด ฐานรองรับ และสถานะการยืนยันตรงกันทุกวิธีควบคุม |
| สถานะผิดพลาด | อธิบายว่าผิดตรงไหนและแก้อย่างไร วางข้อความใกล้ปัญหาและเก็บค่าที่กรอกไว้ | ลองช่องว่าง ค่าผิด รหัสผิด พื้นที่เต็ม ข้อมูลเก่า และตำแหน่งถูกจองโดยคนอื่น | ป้องกันการบันทึกที่ผิด ผู้ใช้แก้และลองใหม่ได้โดยไม่เริ่มทั้งหมดใหม่ |
| ความหนาแน่นและพื้นที่ว่าง | ลดกรอบซ้อน พื้นหลังและข้อมูลซ้ำ ให้ข้อมูลที่ใช้ตัดสินใจเด่น | เทียบภาพก่อน–หลังด้วยข้อมูลสั้น ยาว น้อย และมาก | ข้อมูลสำคัญครบ ไม่ถูกตัดหรือซ่อน และค้นหาสิ่งที่ต้องใช้ได้ง่ายขึ้น |
| รายการสินค้าและตัวกรอง | แสดงจำนวนและสถานะให้ชัด รักษาคำค้น ตัวกรอง และรูปแบบรายการเมื่อกลับจากรายละเอียด | ค้นหา กรอง สลับการ์ด/รายการ เปิดรายละเอียดแล้วกลับ ตรวจผลลัพธ์ว่าง | ผลลัพธ์ถูกต้อง บริบทไม่หาย และมีทางล้างตัวกรองเมื่อไม่พบข้อมูล |
| จำนวนสินค้าและหน่วยจัดเก็บ | แยกจำนวนสินค้ารวม จำนวนต่อหน่วย และจำนวนหน่วยที่ยังใช้งานให้ชัด | ตรวจสินค้าไม่มีหน่วย หน่วยหลายรูปแบบ หน่วย retired และการแบ่ง 4 → 2 | แสดงสอง active units หลังแบ่ง 4 → 2 ตามข้อมูลจริง ไม่รวม retired และไม่ทำให้เข้าใจว่าปรับค่าเริ่มต้นแล้วหน่วยเดิมเปลี่ยนเอง |
| มือถือ | ปุ่มแตะง่าย ไม่มีเนื้อหาล้น การลากไม่แย่งการเลื่อน และปุ่มหลักไม่บังเนื้อหา | ตรวจจอแคบ แนวตั้ง/แนวนอน ขณะคีย์บอร์ดเปิด และการลากบนอุปกรณ์สัมผัส | ทำงานหลักได้ครบ ช่องกรอก ข้อผิดพลาดและปุ่มไม่ถูกบัง ไม่มีการเลื่อนแนวนอนทั้งหน้าโดยไม่จำเป็น |
| คีย์บอร์ดและ accessibility | ลำดับ focus เป็นธรรมชาติ มองเห็น focus และคืน focus หลังปิด dialog | ใช้ Tab, Shift+Tab, Enter และ Escape ตรวจชื่อปุ่ม/ช่องกรอกและ dialog | ทำงานสำคัญได้โดยไม่ใช้เมาส์ ไม่มี focus หลุดหรือค้างในส่วนที่ปิดแล้ว |
| ความต่อเนื่องของ flow | แสดง loading/success ชัด ป้องกันส่งซ้ำ และกลับมาทำต่อจากสถานะที่บันทึกแล้ว | กดซ้ำ รีเฟรช สลับภาษา เปิด direct URL จำลองเครือข่ายผิดพลาดและลองใหม่ | ไม่สร้างรายการซ้ำ สถานะตรงกับข้อมูลที่บันทึก และมีทางทำต่อหรือแก้ปัญหา |

## ขั้นตอนที่ควรพิจารณารวม

- **ปรับตำแหน่ง → ใช้ตำแหน่งนี้ → ตรวจสอบ:** ตรวจว่าปรับได้ในหน้าหลักและแสดงสรุปข้างภาพเลยหรือไม่ เพื่อตัดขั้นที่เพียงเปลี่ยนโหมดหรือแสดงข้อมูลเดิม
- **เปิดรายละเอียดเพื่อทำงานรอง:** พิจารณาให้แก้ไขหรือเปิดตำแหน่งจากรายการได้โดยตรง เมื่อมีข้อมูลเพียงพอและไม่ทำให้ปุ่มแน่นเกินไป
- **เลือกค่าเดิมซ้ำ:** รักษาคลังสินค้า ตัวกรอง และบริบทหน้าที่กลับมา ใช้ค่าเริ่มต้นเฉพาะเมื่อผู้ใช้ยังตรวจเห็นและแก้ได้
- **dialog ยืนยันทั่วไป:** ตัดหรือรวมเฉพาะรายการที่ไม่ได้เพิ่มข้อมูลหรือป้องกันความผิดพลาดที่มีนัยสำคัญ

การจองพื้นที่ การตรวจตัวตนพาเลท และการยืนยันการวางจริงเป็นคนละเหตุการณ์ ไม่รวมให้กลายเป็นการยืนยันทางกายภาพโดยอัตโนมัติ

## วิธีดำเนินการและหลักฐาน

1. เดิน flow ปัจจุบันด้วยข้อมูล QA บันทึกภาพ ขั้นตอน จำนวนคลิก และจุดที่ต้องย้อนกลับ
2. จัดปัญหาตามผลกระทบ: ทำงานไม่ได้หรือเข้าใจผิด → ขั้นตอนซ้ำ → ความชัดเจนของสถานะและสี → รายละเอียดภาพ
3. ระบุการเปลี่ยนแปลงที่เสนอและเกณฑ์ผ่านก่อนแก้แต่ละข้อ
4. ปรับเป็นชุดเล็ก ตรวจโค้ดและทดสอบพฤติกรรมที่ได้รับผลกระทบ
5. เปรียบเทียบก่อน–หลังด้วยงานและข้อมูลเดียวกัน ทั้ง desktop/mobile และไทย/อังกฤษ
6. เดิน flow รวมอีกครั้ง เก็บ screenshots วิดีโอ ผลทดสอบ และข้อจำกัดที่ยังตรวจไม่ได้

## Regression ที่ต้องรักษา

- FG และชุดจัดเตรียมยังแก้ไขได้ตามสิทธิ์และสถานะที่อนุญาต
- การแบ่ง 4 → 2 ให้สอง active units และรักษาจำนวนสินค้ารวมตามรายการที่ยืนยัน
- หน่วย retired ไม่กลับมาเป็นตัวเลือกจัดเก็บหรือซ้อน
- การ preview หรือซ้อนพาเลทไม่เปลี่ยนจำนวนสินค้า
- จองตำแหน่งซ้อนแล้วฐานถูกล็อก การย้าย upper ออกจะปลดล็อกเมื่อยืนยันจบตาม workflow
- Cancel, return, refresh และ retry ไม่ปล่อยพื้นที่ที่ยังต้องกันไว้หรือสร้างรายการซ้ำ
- รหัสผิดและตำแหน่งผิดไม่ผ่านการยืนยัน
- กฎน้ำหนัก/รับน้ำหนักยังอยู่นอกขอบเขตตามข้อกำหนดเดิม

## เกณฑ์สรุปงาน

- มีหลักฐานว่าขั้นตอนที่ซ้ำลดลง และข้อมูลที่จำเป็นต่อการตัดสินใจยังครบ
- ไม่มีทางตัน ปุ่มกำกวม ข้อความที่แนะนำสิ่งที่ทำไม่ได้ หรือสถานะที่แยกได้ด้วยสีอย่างเดียว
- ผ่านการตรวจหน้าจอและ flow ที่เกี่ยวข้อง พร้อม regression tests
- รายงานแยกสิ่งที่ทดสอบจริง สิ่งที่ผ่าน automated tests และสิ่งที่ยังมีข้อจำกัด ไม่ถือว่า viewport จำลองแทนการทดสอบอุปกรณ์สัมผัสจริง

## ผล implementation — 7 กันยายน 2026

- เปิดปรับตำแหน่งในหน้าหลัก ตัดปุ่มเปลี่ยนโหมดซ้ำ จาก **4 → 2 คลิก** หลังแก้พิกัดก่อนจอง โดยยังตรวจปลายทางก่อนจองและยืนยันการวางจริงแยกกัน
- จำคำค้น ตัวกรอง แท็บ และรูปแบบรายการตามผู้ใช้/คลังสินค้า
- แก้ช่องพิกัดว่างไม่ให้กลายเป็นศูนย์, retry การแบ่งบรรจุภายใน dialog, คืน keyboard focus, ขยายปุ่มย้อนกลับ/ลบ และแสดงข้อความงานสำคัญบนมือถือ
- แยกภาพของเดิม/แพ็คที่เสนอ รักษาการซ้อนอัตโนมัติและกฎเดิม
