# Back navigation contract

Back first dismisses the foreground surface or returns to an earlier workflow step. Otherwise it restores the actual browser origin, including locale, query parameters, and hash. A direct child link uses a validated module parent. A direct hub has no synthetic parent and cannot navigate to itself. An in-flight write remains protected. Completing or explicitly canceling an owned step consumes its entry; replacing that entry with its predecessor leaves a dead Back step and is incorrect.

`back-navigation.json` is the reviewed inventory, not a generated allowlist. It includes every production `src/app/**/page.tsx` and error/not-found entry, exact rendered screen targets, individual local state/overlay owners, and navigation action intent. Identities use `file#function:state` or `file#function:$navigate|$task:method:destinationFamily`, never line numbers or content hashes. Adding or renaming a state/action, deleting an integration, changing a route's screen, or adding a route requires an explicit review of its Back behavior.

## Implementing a view

- Use `useWorkflowStep` for an earlier whole-view step. Opening calls the specific step's `enter()`; rendering follows `active`, or the predecessor callback closes the specifically connected local state. Merely declaring a hook or mentioning a state in its availability condition does not establish a predecessor.
- Use shared `Dialog`, `Sheet`, or `ConfirmDialog` for modal surfaces. They own foreground history through `useBackDisclosure`. Exact audited delegators such as `BatchManager` and the search loader must still render their recorded shared overlay owner. Independent camera, registration, and confirmation panes require their own workflow/disclosure ownership.
- URL-backed selections use `useUrlBackedState` for restoration, plus guarded shared traversal for explicit closure. Caller tests must cover the entire open → close → next Back chain; URL synchronization alone does not prove that close consumes history correctly.
- Use `returnFromTask(parent, router.replace)` for task cancellation and `op.complete(() => completeTask(destination, router.replace))` for asynchronous completion. `useTaskCompletion(pending)` supports callers whose pending registration settles separately. Passing `router.push` as the replacement callback is forbidden. Every route action declares `advance`, `dispatch`, `return`, or `completion`; `useGuardedUrl` calls participate in the same inventory. An explicit Cancel/Close/Back-to-list/Done callback cannot push its parent under an `advance` label.
- The Employees same-page editor closure has one exact `urlReturnOwners` declaration: it validates list provenance, traverses an owned entry, or replaces only editor parameters on direct entry. Its URL state and shared traversal must remain present. The synchronous ProductBatches manager exit has an exact `synchronous-exit` declaration backed by actual correction closure cases; adding async/await invalidates that exception. These do not permit other feature return/completion shortcuts.
- Pass `backFallbackHref` as a safe internal parent, or provide a nonempty safe parent breadcrumb. Literal `null` explicitly declares a hub: real origin/foreground Back remains available, direct entry creates no synthetic parent. `showBack={false}` is reserved for audited authentication/denial surfaces. Validate external/query return intent with `safeInternalReturnHref`, `plannerReturnPath`, or the reviewed `pageBackFallback` resolver.
- Pending writes block disclosure/step departure. Preserve the retained underlay draft when dismissing a foreground surface, but require consent before discarding that surface's own unfinished form.

Ordinary filters, form fields, hardware loading/error states, tooltips, inline accordions, and visual preferences are not automatically predecessors. Each detected render-controlling state has an exact audited presentation declaration explaining why. A terminal mutation receipt is not a reason to resurrect an editable command on Back. Presentation entries record branch shape and canonical component/role targets for each truthy/falsy branch, plus hidden/open uses. Repurposing an existing flag to render Location versus TicketForm fails even when its name and `branch` use stay identical. Copy, whitespace, and import aliases do not change those semantic targets. These are individual decisions, not directory exemptions.

## Enforcement and evidence

`navigation/architecture` is a TypeScript-AST ESLint rule. It follows imported/local aliases, namespace imports, destructured methods, literal/computed method names, bound traversal, simple same-file router-return wrappers, and same-file JSX prop-to-destructured-parameter state flow. Opaque computed router calls fail closed. Sensitive navigation reexports need exact verified canonical facade aliases; wildcard reexports are rejected. It rejects raw router/native history operations outside exact infrastructure functions, direct Radix/native modal bypasses, disabled overlay ownership, unsafe header/return destinations, undeclared render-controlling states/actions, removed state-specific integration, parent pushes on explicit exit callbacks, and asynchronous completion without a live shared owner. Infrastructure exceptions are documented by file, function, capability, and, for a nested exception, containing function.

`pnpm ci:navigation` scans production TypeScript as data and checks the full manifest. New routes/error entries fail without a policy; screen migrations, stale/duplicate owners/actions, self/external parents, missing integration, and nonexistent evidence fail. It follows rendered wrappers to compare known Header parent/hub intent with the route policy. The exact `headerBackProviders` entry for `HrShared.useHrBack` permits its canonical hook result to be spread into a Header; arbitrary prop spreads remain undeclared. The hook uses reviewed module parents and a null fallback for hubs, including the newer announcement, leave, payslip, and frozen-history child routes. Employees and Review lists explicitly declare a conditional parent helper for direct selected-query links. Required evidence names literal existing `it`/`test` titles, including parameterized title templates; a generic existing file or arbitrary string in its body is insufficient. This validates the reference, not that a test passed. The checker never executes source, reads environment/authentication state, runs a server, or writes the workspace.

`pnpm test:navigation` explicitly runs Node's architecture/checker fixtures. The files use `*-tests.mjs` names because this repository's existing test-discovery gate accounts for Vitest/Playwright tests, and these fixtures have their own explicit runner. `pnpm check:navigation` runs fixtures and inventory together. The normal `pnpm check` and the credential-free quality validation job include it; normal lint also runs the architecture rule. Release jobs and other lint rules remain intact.

The fixtures reject the original local-state-only Location view, a dormant relevant hook, an undeclared route, parent-policy drift, aliased/destructured/computed/bound Back, raw modal primitives, invalid parents, query returns through both router and guarded URL helpers, missing/invented case evidence, reused presentation exceptions, parent pushes on exit, and unowned asynchronous completion. Positive fixtures exercise connected steps/events, shared overlays, validated parents/hubs, canonical aliases, explicit presentation, and narrow nested infrastructure ownership.

Runtime evidence remains essential. Current HR caller regressions cover announcement editor/receipt foreground ordering and leave-history/returned-edit draft protection as well as the earlier creation and selection families. Concrete workflow families reference their real caller test files in the manifest: HR creation/confirmation/selection, move destination, storage editor/impact flows, job scan/Location, batch review/completion, and Employees editor closure. Shared ordering tests cover nested foreground priority, dirty/pending drafts, Back/Forward, and entry cleanup. Shared tests support overlay infrastructure; they do not replace the concrete caller regressions.

Evidence has practical limits: unchanged dynamic child parents reference the tested module resolver where a full caller direct-link case is unavailable. The unchanged access-derived HrLandingRedirect dispatch references shared replacement behavior and has no dedicated caller regression. Hardware acquisition cases may substitute camera/decoder resources; the referenced callback/selection cases and shared disclosure tests do not establish behavior on every physical device. Inventory declarations should retain those limits and add a concrete caller case when that behavior changes.

## Static limits

An AST inventory cannot prove browser timing, server-write ordering, every closure's temporal behavior, focus cleanup, or the truth of a human presentation decision. Arbitrary inter-module wrappers, complex return-value computation, reassigned mutable aliases, computed native history properties, and opaque third-party components are not fully analyzed. Approved wrappers and destination builders are explicit, narrow dependencies; changes to their behavior need tests and review. Known conditional targets make semantic drift visible, but cannot infer whether a newly added component internally becomes a modal. A connected `enter()` call does not prove every event path reaches it. Same-ID action checks run at every call site, so an earlier synchronous call does not excuse a later post-await call. Caller-level native history tests must cover cancellation, success, direct links, query/hash, dirty/pending state, nested overlays, Forward, and remounts. These checks prevent known omissions and make navigation state reviewable; they cannot promise that all future runtime mistakes are impossible.

When extending the manifest, explain the exact state or route behavior and reference existing regression evidence. Do not label a whole-view camera/editor/confirmation as presentation just to make CI pass, add directory allowlists, invent test paths, or regenerate policies blindly from the scanner.
