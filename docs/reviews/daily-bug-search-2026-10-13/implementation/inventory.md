## Revision rollout and replay compatibility

Schema revisions are optional so existing rows remain readable without an eager database migration. Missing product or measurement revisions mean baseline zero; the first revision-aware write upgrades the row transactionally. New products start at revision one; new legacy pallets start at measurement revision zero. Revisions increment independently of timestamps, and a test deliberately collides timestamps while preserving conflict detection.

The public `expectedRevision` argument remains optional at the validator boundary to preserve callable argument shapes and old exact retries. Fresh updates without a baseline are refused with `VERSION_CONFLICT`; creates remain supported. `command()` performs request fingerprint and success-receipt recovery before revision/lifecycle checks. Tests cover exact retries after a newer save, changed arguments with the same identity, and pre-rollout success receipts whose arguments lacked `expectedRevision`.

A retained old local draft without revision metadata is preserved with an unusable baseline and an explicit reload option. The caller does not silently attach the current server revision to stale text. Users can copy their edits before choosing the clearly labeled discard-and-reload action. Invalid old fractional product defaults are refused rather than rounded; repair requires setting a valid default through the authorized product API.

## Cursor bounds and behavior

Each request makes one native pagination call, requesting at most 100 rows. The existing tenant storage adapter caps that call at 101 rows read and 524,288 bytes. Native ordering includes index creation-time tie ordering. Filtering retains the native continuation and native completion signal, so a page with no matches does not imply that older history has no match. Users can advance that page, and the Records empty state explains this behavior. These are anchored live continuations, not frozen result-set snapshots: newer records before an existing boundary are seen after returning to the first page.

## Additional confirmed issue — ROOT-04 (P2)

This issue was confirmed during follow-up diagnosis requested by the parent implementation agent; it is not an invented entry in the historical final ranking. The unchanged baseline's whole `StorageLayoutScreens.test.tsx` reproduced **79 passed / 1 failed**: `Close dialog dismisses the mobile zone editor with the shell guard and consumes its entry before the next Back (dirty: false)`. The case also failed in the isolated inventory worktree before this follow-up, while its isolated run passed.

A temporary, removed test-only history trace identified a real handoff race. The building entered at app history index 1 and its location details Sheet pushed index 2. Clicking Edit called `setSheetSelection(undefined)`, which requested asynchronous native Back, while `onCloseAutoFocus` independently scheduled the editor action in a frame. The editor pushed index 3 before the earlier Sheet traversal arrived. Two queued closure Back requests reached index 2; removing both visible overlay flags there left a second building entry. The next Back reached building index 1 instead of the real origin at index 0. No dirty guard buffer was involved in that failing pristine trace.

The narrow fix adds an optional Sheet completion ref matching the existing Dialog interface. FloorMap dispatches its inspector action only after the Sheet's shared workflow consumes the owned native entry **and** Radix releases focus. The next frame still lets the old focus trap finish. A handoff identity, current route check and unmount cleanup prevent stale frame dispatch. Ordinary inspector closure retains its prior focus restoration, and all dirty/pending decisions still go through the shared guard.

The added literal caller case, `waits for native inspector history consumption and focus release before opening its zone editor`, deliberately holds the actual native Back beyond three separately flushed frames. It was verified **red against the original FloorMap**, where the editor opened before traversal release, and **green with the fix**, where the entry stays at index 2 until release, the editor then owns index 2 after the Sheet is consumed, focus belongs to the editor, closing consumes its entry, and the next Back restores the original locale/query/hash route. Historical case expectations were not changed.
