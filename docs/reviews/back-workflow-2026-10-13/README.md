# App-wide Back correctness and prevention — 2026-10-13

The reported Location → Back interaction is fixed, and the same Back contract now applies across the app. Codex subordinates implemented runtime, safe parent policy, tests and CI enforcement; the primary agent coordinated and reviewed, with independent Codex and Kiro audits. No commit, push, deployment, seeding or business mutation was performed. Existing dirty work, saved local backend data and the October 12 fixes were preserved.

## Contract and coverage

Back handles the foreground interaction or previous workflow view first, preserving retained drafts. Page departure then uses the actual app origin including relevant locale/query/hash. Direct links use a validated parent within their module; a module hub without a predecessor disables Back. Pending business writes remain protected. Explicit Cancel and successful completion consume their owned native entries so later Back/Forward cannot reopen abandoned forms or invisible steps.

The versioned [developer contract](../../contracts/back-navigation.md) and [machine inventory](../../contracts/back-navigation.json) cover **43 route/error policies, 187 exact state/overlay owners and 24 action intents**, backed by literal cases in **29 caller/shared test files**. [The route/control inventory](inventory.md) lists every route and records the changed versus presentation/already-integrated caller families. This is a source-wide contract and enforcement pass; it does not imply a browser visit to every data-dependent route.

Native History/query/Next router state remains the shared mechanism. No parallel history stack was added. Shared Dialog/Sheet wrappers own foreground entries; workflow callers use `useWorkflowStep`; task returns/completion use the existing native entry provenance through sanctioned helpers. Next tree metadata is retained correctly without copying removed/stale ownership. Guard consent and accepted discard apply only to the abandoned draft; underlying dirty forms remain intact.

## Durable prevention

The normal ESLint rule analyzes imported aliases, destructured/computed/bound native/router traversal, same-file wrappers and state passed to branching children. It rejects unowned state-only foregrounds (including the original Location pattern), unsafe/missing/self Header parents, direct modal primitive bypasses, abandoned-task parent pushes, and post-await navigation without a live completion owner. Exceptions are exact infrastructure functions/capabilities, never entire feature directories.

`pnpm check:navigation` verifies route/control/action drift and actual literal evidence references. **64 positive/negative fixtures** prove that representative unsafe code goes red and connected shared ownership goes green. The normal `pnpm lint`, `pnpm check` and quality CI job run the rule/gate. AGENTS.md links the contract while retaining the generated Next block. The checker treats source as data and does not execute app/auth code.

AST enforcement cannot prove every temporal closure, hardware behavior or human presentation decision. Runtime caller tests remain required; the contract states those limits and disallows broad exceptions used merely to make the gate pass.
