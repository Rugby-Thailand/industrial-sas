## Polish round: period row version label

Root's native browser check (not run here) found the following. For "ส่งออกงวด 19–25 ก.ย. 2569 ฉบับ 1", the row correctly opened version 1 with export focus, where `latestClosedVersion` is 4. However, its detail read "LOCAL-DEMO · ปิดแล้ว ฉบับที่ 4", which described a different version from the one the row opens.

- Fix: in `results.tsx`, `choiceResult` builds the detail of an openable PERIOD row from the version its target opens. It reuses the translated `periodClosed` label. A version is named only when it is a whole number from 1 to `latestClosedVersion`. Otherwise the row keeps `periodDetail`. A row with no version requested still shows the latest version or "Draft". Disabled rows (unavailable or invalid version) still show `periodDetail` with their reason. Normal and AI choices share this path. The resolver, provider, lookups and targets are unchanged.
- Regression: `GlobalSearch.test.tsx` "opens the version written in the text…" (extended) and "names the requested version on an AI period choice" (new). Both use `latestClosedVersion: 4`:
  - The native query's row shows "HQ · Closed, version 1", not version 4, and opens `/hr/periods/p1?version=1&focus=export`.
  - With no version, the row shows version 4.
  - `ฉบับ 9` and `ฉบับ abc` stay `aria-disabled`. They show the "not available" and "could not be read" hints, keep "Closed, version 4" as the period state, and do not navigate.
  - The AI inferred-year choice for version 1 shows version 1 and opens version 1.
- Mutation check: restoring `periodDetail(choice.period)` made both tests fail.
- Formatting: `src/lib/deepLink.ts` was reformatted by Prettier (whitespace only).

- Name search is still a bounded substring pilot with no Thai segmentation. Incomplete reads are reported, never concluded.
