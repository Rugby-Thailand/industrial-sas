## Limitations

- **Stacking compatibility:** `saveStackingLimits` refuses a save with no baseline, so a tab still running the old frontend cannot save stacking limits until it reloads. Reads, reservations and the pallet editor are unaffected. This follows the documented fail-closed version policy.
- **HR reconciliation:** the changed-record alert does not show a field-by-field comparison. The current record stays visible in the surrounding day detail.
- **Shortcut errors:** `PREFERENCES_INVALID` still shows the generic HR refusal. It was not part of the confirmed finding.
- **Test boundaries:** the UI tests replace Convex subscriptions with controlled results, and the backend tests use the in-memory tenant harness. Production network timing and a real browser were not exercised. No deployment, production record or Convex backend was used.
- **Flaky test seen once:** `StorageLayoutNavigation.test.tsx`, "native Back cancels a spot archive confirmation and the next Back leaves the building", failed once while the whole storage directory ran in parallel. It passed 5 of 5 times in isolation and on every later run, and it passed 3 of 3 times on unchanged `HEAD`. Its source and test are unchanged here.
