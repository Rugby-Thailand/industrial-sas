# Kiro UX/UI and missing-flow review — 15 October 2026

Three independent Kiro CLI agents (`claude-opus-5.5`, high effort) reviewed **HR**, **finished goods and scanning**, and **storage layouts with shared navigation**. They reviewed the current working tree, including existing uncommitted work. The parent checked source paths, independently replayed all three probe suites, and exercised the existing storage component preview.

The review found **eight new substantive flow defects (one P1, seven P2)**, **six smaller UX observations**, and **one previously reported warehouse-switch defect with additional runtime evidence**. “New” means not found in the prior reports checked by the reviewers. This is a bounded search, not proof that the rest of the app is defect-free.

Application code was not changed. Reports, reproduction probes and evidence are saved here. No production records, commits, PRs or deployments were created.

## Previously known issue and parent correction

**FG-UX-05 / storage-actions F05:** changing the warehouse in another tab can remount Job tickets and lose unsent tickets without a prompt. The real warehouse store plus JobScanScreen probe reproduced this, extending the earlier source-only evidence. It is **not a new finding**.

The raw finished-goods report also describes changing the warehouse in the current task's header. The parent did **not** establish that user path: the current shell hides its selector on task routes. The same-tab probe calls `writeStoredWarehouse` directly, so it proves an unguarded store transition, not a visible header action on Job tickets. The cross-tab path remains relevant. Prioritize preserving or guarding drafts on external context changes; do not expose additional task-page switching without the same protection.
