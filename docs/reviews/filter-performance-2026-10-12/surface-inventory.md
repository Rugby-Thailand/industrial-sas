# Search, filter, and pagination surface inventory

Research snapshot: 2026-10-12, isolated `industrial-sas-filter-research` worktree containing the current workspace, including its HR work. This is a source audit and baseline test result, not an implementation or a claim that the deployed app matches this snapshot. The parent investigation owns live browser measurements. In particular, the production sidebar exposes AI usage while no corresponding route exists in this source tree.

## Findings that change the plan

1. Most storage/finished-goods collection pages already have pagination. Several still scan the whole matching universe before exposing a page. Adding another footer would not fix their latency.
2. Scanned-record text search reads up to 10,000 records on every page and then offset-slices them. This is the clearest adjacent full-history bottleneck.
3. Storage location text search advances one zone at a time, often across two or more client/server requests per zone. Building/floor filters currently run after that warehouse-wide scan.
4. HR has important missing continuation: employees, periods, review queues, settings holidays, members, and employee audit. Most caps are explicitly reported; the period detail exception list silently displays only its first 200 items.
5. A floor table's local pagination reduces DOM size, but its caller still fetches geometry for an entire building plus building-wide inventory. Query scope and visual pagination need separate changes.

## Shared contracts and navigation requirements

- [useCursorPagination](../../../src/hooks/useCursorPagination.ts) already resets on criteria/page-size change, restores from `history.state`/a bounded in-memory map, listens to `popstate`, and retains at most24 scopes /500 cursor entries. Keep this behavior, including first-page recovery after cursor history is trimmed.
- [useCatalogueSync](../../../src/hooks/useCatalogueSync.ts) handles scanning continuations, one reset attempt, and moving backward when the terminal page becomes empty. [paginatedScan](../../../convex/lib/cataloguePagination.ts) preserves range splits, tenant/actor criteria scopes and retained-ID reauthorization. These are correctness features to retain, even if fast query paths stop using iterative scans.
- [useCatalogueState](../../../src/features/finishedGoods/useCatalogueState.ts), [useLocationCatalogueState](../../../src/features/storageLayouts/useLocationCatalogueState.ts), and [useQueryHistoryWriter](../../../src/hooks/useQueryHistoryWriter.ts) preserve URL filters and collapse successive typing into one history step. Scan records, picker, and HR requests use local criteria and need equivalent return/back/forward restoration.
- Some cursor scopes only contain warehouse (`job-scans`, named locations). Standardize organization/actor/warehouse/surface scoping, while continuing to clear state on identity change. A client scope is never authorization; the server must enforce tenant/site permissions independently.
- Filters must apply to the whole result set before logical pagination. Counts must clearly say whether they cover the full filtered set, current page, or a bounded/incomplete scan. Building options must come from independent authorized metadata, never just the visible location page.
- Keep filter changes/page size resetting to page1; preserve search, filters, sort, page, selected row and scroll when opening a detail and returning. Handle stale/deleted rows, expired cursors, rapid typing, clearing filters, actor/site changes and two independently paged sections on one route.
- Existing local sizes are25/50/100; cursor sizes20/50/100. HR requests max50 currently. Do not wire one universal select to incompatible APIs.

## Read-limit interpretation

The wrapper's `.all(limit)` is **not silent truncation**: [tenantStorage.indexedBatch](../../../convex/lib/tenantStorage.ts):313 reads `limit + 1` and throws `CAPACITY_DATA_LIMIT` on overflow. `.take(n)` is bounded but does not prove completeness; callers must check an extra row. Native page reads have row/byte limits and can return split statuses. The improvement plan must replace growing full reads with real continuation instead of raising constants or presenting a cap as pagination.
