## Findings ranked by incremental usefulness

### 1. Merge catalogue occupancy/status reads per distinct building (P2; high code confidence, medium savings confidence)

`StorageLayoutScreens.tsx:249` mounts `BuildingStatusToggle` for each displayed building; `:273` also mounts `BuildingCatalogueOccupancy`, whose query is at `:304`. The toggle subscribes at `BuildingStatusToggle.tsx:57–60` only for activation-authorized members and non-archived buildings. Distinct buildings produce distinct `{warehouseId, buildingId}` subscriptions. Two different function names cannot deduplicate even with matching arguments. This confirms the **still relevant** October 10 backend F7 merge opportunity, rather than a new issue.

Incremental remedy: the occupancy result already contains version/status through `...row` (`catalogue.ts:353–355`), so only add `blocked` from that same query snapshot and let catalogue toggles consume it; retain standalone statusControl for the building screen (`StorageLayoutScreens.tsx:547`) and location catalogue (`StorageLocationCatalogue.tsx:372`). Derive blocked from the already-read RESERVED/STORED placements, preserving ACTIVE-only semantics. Preserve transaction-side occupied checks and expectedVersion in writes; an observational query must never authorize a write or replace transactional validation. Do not make status-only screens load full occupancy just to consolidate calls.

Minimal implementation path: move the occupancy query from the area-only child to a dedicated catalogue-row controller, passing its result to both the area view and a shared toggle presenter. Keep the existing standalone toggle wrapper for other screens. This avoids conditional hooks and avoids a new catalogue endpoint. An alternative optional injected-control prop must explicitly distinguish “external control loading/denied” from “standalone subscription mode”; otherwise undefined external data can accidentally start the old query and retain both subscriptions. The catalogue page row supplies initial display identity/status, but occupancy supplies authoritative status/version/blocked for commands; never mix a page-row version with an occupancy blocked verdict. On missing/denied/pending occupancy, disable the toggle and preserve existing unavailable/loading states. Keep errors keyed to authoritative building/warehouse/version/status, as the current toggle does. Deriving blocked from loaded placements introduces no stored projection or secondary source of truth. Verify the placement read completes rather than interpreting a truncated/error result as unoccupied. Compatibility: retain current result fields, existing endpoints and standalone consumers; old clients keep working. Cost risk: forcing toggles to wait for full occupancy couples a previously cheap indexed presence check to a slower/possibly failing broad scan, so reject the merge if measured toggle latency or availability worsens materially.

Mechanism: removes one separate authenticated query execution and its authorization/context reads per distinct catalogue building on cold loads and eligible reruns. It does **not** remove occupancy scans. `catalogue.ts:32–52` already uses indexed `.first()` for presence; statusControl is not a full placement scan. A combined query may share occupancy's broader invalidation set and may delay toggle readiness until occupancy completes. Display-only badges for users without activation rights already skip statusControl, so their call savings are zero.

Measure: compare a fixed 20-building page before/after with ordinary read-only versus activation-authorized accounts; record unique websocket query Adds, per-function cache misses, execution read bytes/documents, p50/p95 toggle-ready latency, and resulting combined-query invalidations. Repeat placement insert/update/remove and status write; regression cases include archived, draft, blocked, version conflict, revoked permission and warehouse switch. Do not multiply location row count by backend execution count.

### 2. HR date calculation affects a subscription mounted across the locale tree (P2; high evidence, unmeasured frequency)

`src/app/[locale]/layout.tsx:83` wraps all locale children in AppProviders. `AppProviders.tsx:26–28` places HrAccessProvider alongside the workspace provider, regardless of storage versus HR route. `HrAccessProvider.tsx:50–53` subscribes to HR access for authenticated users. `convex/hr/access.ts:28` invokes `orgClock`; `convex/hr/shared.ts:66` reads Date.now. This is separate from workspace/current, whose ordinary authorization clock issue was fixed September 29.

Convex's documented clock/cache warning therefore still applies to successful HR access reads on storage pages. Official best-practices documentation explicitly says subscriptions do not rerun just because Date.now changes; cache expiry reduces reuse on later calls and is distinct from proactive reexecution. There is no timer or demonstrated fixed rerun cadence. The checked public docs do not specify a five-second expiry, so this report does not assert that interval. Members denied HR access stop before the handler and need not incur this handler clock dependency. This finding overlaps the HR backend audit and should be consolidated there.

Incremental remedy: consider separating stable HR display grants/profile/sites from business-date display data, then subscribe to the date only where actually consumed. Alternatively use a coarse date input for display, with explicit timezone and midnight/focus refresh rules. Server authorization and HR write validation must continue using trusted server time; client-provided date must never determine access/period validity. Splitting adds an extra endpoint/subscription where both are needed; measure before implementing. Merely returning fewer fields while retaining orgClock does not remove its cache dependency.

Measure: HR-enabled account on storage page, denied-HR account, and HR page; compare cache age/hit rate and read bytes across fresh tabs and navigation. Test local-business midnight, stale hidden tab returning to focus, supported/unsupported timezone, account switch and revocation. Check current source and HR reviewer recommendations before undertaking overlapping work.

### 3. Investigate dependency invalidation behind workspace's 34K calls before changing its lifetime (measurement priority; high trace confidence)

There is one workspace hook (`WorkspaceProvider.tsx:90–93`) with stable `{}` args after Convex authentication. Consumers use React context, not additional workspace queries. Client is created once using useState in `ConvexClientProvider.tsx:17–19`, and locale layout persists through normal desktop navigation. Warehouse selection changes context/local storage; it does not add a warehouse argument to readCurrent. Thus calls cannot be explained by number of `useWorkspace()` consumers or each React rerender.

Backend `workspace/current.ts:63` resolves allowed warehouses plus grantedNavigationPermissions. Warehouse reads are bounded to 100 (`:33–61`); permission grants probe membership roles, active roles, and role-permission points (`navigationGrants.ts:25–58`). Shared tenant resolution also reads user, organization and current membership (`tenantFunctions.ts:458–467`, `tenantContextLookups.ts:37–105`). Changes to dependency documents can invalidate a long-lived workspace query even when its returned organization/name/permissions remain the same. Whether actual production writes frequently touch those documents is unproven here.

Remedy sequence: first correlate execution spikes/cache misses with deployment, identity refresh, hard reloads, concurrent tabs/users, membership/role edits, warehouse edits and organization/user document writes. If broad unrelated fields on organization/user documents are responsible, evaluate a narrower maintained access/display projection with explicit transactional synchronization. Do not unsubscribe workspace on HR routes as a first fix: shell search, navigation guards and HR landing redirect consume its readiness/denial. Do not cache authorization grants in localStorage or remove reactive revocation dependencies.

Mechanism: fewer reactive cache invalidations reduce actual uncached reads; moving the hook lower may reduce initial subscriptions but creates readiness waterfalls and loses shell context. Payload trimming affects transfer/client work, not database bytes of documents already read. A concrete remaining backend opportunity is `grantedPermissionsAmong`: `navigationGrants.ts:41–58` still loops over each permission and each active role, issuing sequential unique point reads until a grant matches. Consider one bounded per-role permission range read followed by in-memory intersection, reusing already-resolved authorization roles where safe. This can reduce query/range overhead and dependency probes but may read more permission document bytes; benchmark sparse versus dense roles. Preserve org scoping, ACTIVE role filtering, membership limits, completeness/denial semantics and immediate revocation. This is not the previously implemented request-ID clock or membership-status lookup fix. Coordinate this higher-confidence concrete remedy with the backend reviewer before projection work.

## False-positive safeguards and already completed work

- Identical location-row toggles are deduplicated by the single client. `StorageLocationCatalogue.tsx:372` passes building/warehouse, not zone ID; many zones belonging to one building share a query. Installed SDK `node_modules/convex/src/browser/sync/local_state.ts:98–108` uses serialized path/args and subscriber reference counts, removing the backend subscription only after the final subscriber leaves (`:372–380`). Counting hooks is not counting backend executions. A shared row provider may reduce local React work but is not itself an I/O optimization.
- Fresh object literals are safe: installed React hook dependencies serialize Convex args (`node_modules/convex/src/react/client.ts:945,1020`). No Date.now, nonce, random ID, or installation ID enters these audited read arguments. Different page/search/cursor/building values intentionally produce different query identities.
- September layout/inventory split remains implemented: `useStorageBuilding.ts:21–23` independently subscribes to layout and inventory. Building, floor-editor and review consumers are at `StorageLayoutScreens.tsx:517,1130,2898`. Do not re-propose the split or remove inventory reactivity.
- Closed space-details dialog is gated with `open` (`BuildingAreaDetails.tsx:48–54`), which makes both split hooks use `skip`. Location details read only while its details element is expanded (`StorageLocationCatalogue.tsx:479–482`). Global search body mounts only while open (`SearchDialogLoader.tsx:101–110`); cached imported JavaScript is not a retained data subscription.
- All displayed catalogue buildings subscribe even below the fold. That is actual lifetime behavior, not a hidden dialog bug. Visibility gating or virtualizing could reduce subscriptions for very large pages, but it changes readiness/accessibility and can churn subscriptions while scrolling. Prefer the smaller merge above; quantify large-page usage before pursuing viewport lifecycle work.
- `NamedLocationCatalogue` stays visible and queried beneath both location views (`StorageLocationCatalogue.tsx:449–457`, `NamedLocationCatalogue.tsx:46`); this is rendered content, not a hidden background feature. Gating it requires a UX decision, not an automatic cost fix.
- No preloadQuery/usePreloadedQuery/fetchQuery or setInterval was found in current application TypeScript/TSX source. Next Link prefetch is route/code prefetch here, not evidence of server Convex preload. Do not report duplicate SSR-plus-client executions without an actual preload path.
- Ordinary query request IDs use crypto.randomUUID (`tenantFunctions.ts:455`), and non-expiring already-effective ordinary reads use membership creation time (`:321–333`). This prior fix must not be repeated. Future/expiring membership, custom policy, step-up and writes retain Date.now intentionally. Removing that clock globally changes authorization semantics.
- Per-client deduplication does not equate all users or browser tabs: auth identity is a dependency/cache input, and separate clients have separate local subscriptions. Do not share tenant/user-dependent results outside Convex's authenticated cache.
