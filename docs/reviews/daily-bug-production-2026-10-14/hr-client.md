## Independent review follow-up — recovered shortcut concurrency baseline

The independent spec review confirmed a DAILY-03 variant missed by the first candidate: a lost, uncommitted version-0 preference command remounted after another tab saved version 1. Retry correctly refused the original version 0, but the editor had initialized its baseline from version 1. A subsequent ordinary Save attached the recovered old choices to version 1 and overwrote the other tab. The external cold-storage probe reproduced the version mismatch and actual backend version-1 → version-2 overwrite.

`ShortcutEditor` now initializes a recovered draft's baseline version from its persisted `expectedVersion`, and marks that draft as owned until a confirmed SAVED receipt or explicit Cancel. Stale refusal releases the request ID, so a later Save receives a fresh ID while still sending the original concurrency version. This also protects a recovered draft whose choices happen to match the latest query: value equality alone does not consent to a new baseline. Clean query adoption and highest-version receipt consumption retain their prior behavior. Cancel adopts the latest preferences and releases the owned recovery marker.

A new registered-backend caller regression creates a real uncommitted lost response, unmounts, commits another tab's version-1 choices, and remounts. It proves Retry keeps the exact request ID/payload/version 0; a subsequent ordinary Save gets a new request ID but remains version 0 and is refused; the database stays at version 1 with the other tab's choices. Explicit Cancel then adopts version 1 and the next edit saves version 2. The regression covers both different and matching latest choices.
