## Navigation integration for the parent inventory

All new foregrounds use shared `Dialog` or `ConfirmDialog`, which own history through `useBackDisclosure`. No feature code writes history directly.

- **New render-controlling local states**, each opening a shared `Dialog` or `ConfirmDialog`:
  - `RemoveTopFloor:open`
  - `BuildingArchiveSection:open`
  - `BuildingStatusToggle:confirming`
  - `StorageZonesPanel:archiving` and `StorageZonesPanel:positionsZoneId`
  - `StoragePositionsDialog:archiving`
  - `NamedLocationCatalogue:completing`
- **Presentation only:** `StoragePositionsDialog:editing` swaps the inline add form for an edit form inside the open dialog.
- **Route actions:**
  - `NewBuildingContent` Back button and viewer Back: `$task:returnFromTask` → catalogue (**return**).
  - `NewBuildingContent` create success: `operation.complete(completeTask)` → building (**completion**).
  - `ReviewContent` activation: `operation.complete(completeTask)` → building (**completion**; this replaces the previous `router.push`).
  - **advance** links: `BuildingReviewAction` → review; catalogue Open → `?floor=N`; readiness "Edit floor N" → `storageFloorPath`; `NamedLocationCatalogue` "Open floor N".
  - **dispatch** links: `ArchivedBuildingNotice` → review; `BlockedImpact` unit links → pallet.
- **Pending protection:** every new write uses `navigation: "write"`. The positions, named-layout and confirmation dialogs pass `backPending` while their write is in flight.
- **Draft registration:** the new building form and the dimensions and floor-count forms each register their own draft.
- **Caller evidence:** the ITS New building cases cover origin with query/hash, direct link and completion. Forward and remount for these new dialogs rely on the shared `ForegroundOrdering`/`ForegroundBack` tests; there are no dedicated caller cases.
