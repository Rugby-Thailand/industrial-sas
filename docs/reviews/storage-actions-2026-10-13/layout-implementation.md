## Navigation integration for the parent inventory

No feature code writes history directly. The only traversal helpers used are `useWorkflowStep`, shared `Dialog`/`ConfirmDialog`, `returnFromTask`, `completeTask` and `operation.complete`. Successful writes close their foregrounds only through the live operation owner and the shared `DialogCompletionHandle` or `useWorkflowStep.complete`; there are no deferred listeners or timers.

- **Workflow steps (query key → scope):**
  - `BuildingModelWorkspace`: `editing` → `storage-floor-editor:<building>`.
  - `FloorForm`: `floorImpact` and `floorOffset` → `storage-floor-draft:<building>`.
  - `StorageZonesPanel`: `zoneImpact` → `storage-zone-impact:<w>:<b>:<floor>`.
  - `PositionsManager` (in `StoragePositionsDialog.tsx`): `positionEdit` → `storage-position-edit:<zone>`.
- **Shared overlays:**
  - Overlays and their owner state:
    - Controlled `Dialog`s:
      - `BuildingSettingsDialog`: uncontrolled `Dialog`.
      - `StorageZonesPanel`: zone editor (`createDialogOpen`).
      - `StoragePositionsDialog`: open follows the managed zone (`StorageZonesPanel:positionsZoneId` delegates to it).
      - `CompleteNamedLayoutDialog`: open follows the location (`NamedLocationCatalogue:completing` delegates to it).
      - `ReservedBlocks`: `dialogOpen`.
    - `ConfirmDialog`s:
      - `RemoveTopFloor:open` and `BuildingArchiveSection:open`.
      - `BuildingStatusToggle:confirming` (rendered by `StatusConfirmation`).
      - `StorageZonesPanel:archiving` and `StoragePositionsDialog:archiving`.
    - `LayoutHelpDialog`: uncontrolled `Dialog`.
  - Removed as local render owners:
    - `FloorMap:offsetEditing`: now caller-controlled props.
    - `FloorForm:confirmingImpact`: now derived from `impactStep.active`.
    - `StorageZonesPanel:confirmingImpact`: now derived from `impactStep.active`.
    - `StoragePositionsDialog:editing`: `editing` only holds the row; rendering follows `editStep.active`.
- **Route actions:**
  - `NewBuildingContent`: Back to buildings and viewer Back use `returnFromTask` (**return**); create success uses `operation.complete(completeTask)` (**completion**).
