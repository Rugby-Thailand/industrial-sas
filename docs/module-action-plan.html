03
Shared product rules

กฎร่วมของทุก Action

01
Scan-first, search-second. สแกนเอกสาร → location → tag/SKU → lot/serial; manual entry ต้องมี reason และสิทธิ์
02
Command, not patch. ใช้คำสั่งเฉพาะธุรกิจและ state transition ที่ typed; ห้ามให้ client ส่ง status ใหม่โดยตรง
03
Post แล้วห้ามแก้. ความผิดพลาดแก้ด้วย reverse/correction ที่อ้างรายการเดิม เก็บ before/after, reason และผู้อนุมัติ
04
One stock identity. ทุก movement ระบุ org, warehouse, location, SKU, UOM, lot/serial, tag/HU, owner และ stock status
05
Idempotent by default. ทุก mutation จากเครื่องสแกนมี operationId, deviceId, capturedAt และ expectedVersion
06
Risk decides approval. over/short, negative, expired, manual, backdate, high value, QC disposition และ reconcile ใช้ threshold + maker–checker
07
Attachment inherits access. รูป/เอกสารไม่ public; สิทธิ์ตามเอกสารแม่และทุก download ตรวจสิทธิ์ใหม่
08
Offline has boundaries. scan queue ทำได้ แต่ approve, release, reconcile และ high-risk post ต้อง online ใน MVP
04
Warehouse operations

โมดูลคลังสินค้า

04.1 รับสินค้า

แยก source document แต่ใช้ receipt engine, scan resolution, QC gate และ ledger posting ร่วมกัน

Extend existing
Ready→Receiving→Partial / Pending QA→Posted

รับตามสั่งซื้อ

เลือก/สแกน PO → SKU/Lot/UOM/จำนวน → เทียบยอดค้าง → QC/Quarantine → สร้าง Tag และ Putaway; รองรับ partial, over/under, unexpected และ damaged พร้อม approval

รับตามใบเตรียม

รับ Tag หรือรายการจากต้นทางที่เตรียมแล้ว ตรวจ prepared/sent/received quantity, staging location และ discrepancy ก่อนสร้าง putaway

รับตามใบผลิต

รับ FG/WIP/by-product จาก Production Order บันทึก good/reject/rework, lot genealogy, กะ/เครื่อง และ QC hold ก่อน release

รับอื่น ๆ

คืนลูกค้า, ยืมคืน, found stock, ของแถม หรือ correction ต้องเลือก subtype/reason, แนบหลักฐาน และ Supervisor อนุมัติก่อน Post

Action ที่ควรเพิ่ม

  • นัดหมายรถ / ASN
  • Print GRN, label, tag
  • Hold / release / return supplier
  • Reverse receipt line
  • Close short พร้อมเหตุผล

ข้อมูลและ exception สำคัญ

  • Source document, delivery note, supplier/source
  • ordered / sent / received / accepted / rejected qty
  • duplicate serial, expiry, wrong lot, damaged, unknown SKU
  • ผู้รับ ผู้ตรวจ ผู้อนุมัติ device และเวลา

04.2 จ่ายสินค้า

Action เดิมยังขาดขั้น Allocate → Pick → Check → Pack/Stage → Issue ซึ่งควรเป็นแกนกลางก่อนแยก source document

New slice
Released→Allocated→Picking→Checked / Packed→Issued

จ่ายตามใบสั่งขาย

allocate ตาม SO, แนะนำ FIFO/FEFO, scan location–SKU–lot–tag, short pick/backorder, checker และส่งต่อขนส่ง

จ่ายตามใบกำกับ

ตรวจ invoice/delivery note ว่ายัง valid และไม่จ่ายซ้ำ รองรับ partial delivery และ reverse ตาม credit/cancel document

จ่ายตามใบเตรียม

เบิกให้ฝ่ายผลิตหรือหน่วยงานปลายทาง เก็บ requester, purpose, cost center, lot และ digital handover

จ่ายตามใบหยิบ

scan verify Tote/Pallet และทุกรายการใน Pick List ก่อน Issue; discrepancy สร้าง re-pick task ไม่แก้ยอดเงียบ ๆ

จ่ายอื่น ๆ

sample, internal use, scrap, donation, loan และ emergency issue ใช้ reason, approval matrix, attachment และมูลค่าเป็น threshold

Action ที่ควรเพิ่ม

  • Reserve / allocate / unallocate
  • Wave / batch picking
  • Short pick / substitute / backorder
  • Pack / stage / handover
  • Undo scan / reverse issue

MVP ก่อน

  • SO allocation + pick task
  • FEFO/FIFO explanation
  • dual scan/checker
  • partial fulfillment
  • ledger issue + reversal

04.3 Tag / จัดเก็บ

Tag คือ Handling Unit ที่ trace ได้ ไม่ใช่เพียงรูป Barcode; การเก็บเป็น movement จาก staging ไป location จริง

Extend existing

สร้าง Tag

ผูก source, SKU/lot/serial/qty/package → generate ID → print → scan-back verify → active; เพิ่ม split, merge, repack, nest, reprint และ void พร้อม audit

เก็บตาม Tag

สแกน task/tag → ระบบแนะนำ location ตาม zone/capacity/stock class → scan location → confirm; override ต้องมี reason/permission

Created→Printed→Verified→Active→Consumed / Void

04.4 โอนย้าย

การโอนข้ามคลังต้องเป็นสองขาเสมอ: ตัดต้นทางเข้าถัง In Transit แล้วปลายทางจึงรับเข้า location จริง

New slice
Requested→Approved→Picked→Dispatched / In Transit→Received→Closed

จ่าย/โอนใบสั่งขาย

สร้าง transfer เพื่อ fulfill SO จากคลังต้นทาง; partial, reallocation และ SO cancel ต้องปิด remaining quantity อย่างชัดเจน

จ่าย/โอนใบกำกับ

ตรวจ duplicate dispatch, invoice validity, staging, vehicle/seal และจุดส่ง

จ่าย/โอนใบเตรียม

รองรับ replenishment/production staging ระหว่างคลัง โซน หรือ line พร้อม request purpose

จ่าย/โอนอื่น ๆ

rebalancing, relocation, emergency และ consignment ต้องมี reason/value approval; intercompany costing ไว้ภายหลัง

รับตามใบโอน

scan transfer/seal/tag, เทียบ sent vs received, บันทึก short/over/damage, quarantine หรือ discrepancy approval แล้วสร้าง putaway

04.5 นับสินค้า

Opening stock เป็น migration command แบบครั้งเดียว; cycle count และ reconcile เป็นงานประจำที่แยกผู้ “นับ” ออกจากผู้ “ปรับยอด”

New slice

ตั้งต้น Stock

import/scan opening batch → validate SKU/UOM/location/lot/duplicate → preview → approve → immutable opening ledger; เก็บ file hash และ cut-off

นับสินค้า

cycle/full/spot count แบบ blind, scan location/tag/SKU, freeze หรือ movement-aware snapshot, unknown stock, duplicate protection และ recount threshold

Reconcile

คำนวณ system + movement เทียบ physical → root cause → recount/accept → threshold approval → adjustment transaction → corrective action

Planned→Counting→Submitted→Recount / Review→Approved→Adjusted

08.2 สั่งสินค้า

08.3 ตรวจสอบสินค้า (QC)

ใช้ QC engine กลางกับ 4 บริบท: รับเข้า, ระหว่างผลิต, ผลิตเสร็จ และก่อนจ่าย

Inbound QC exists
Ready→In Progress→Awaiting Review→Disposition→Closed

Plan & sample

สร้างจาก source/manual, เลือก spec/version, lot, sample size, assign inspector และ hold stock

Inspect

บันทึก numeric range/text/choice/boolean, defect severity, instrument และ private photo/lab result

Review & disposition

release, quarantine, reject, rework, conditional release หรือ retest; high risk แยก inspector ออกจาก approver

Nonconformance

Product owner decisions

คำถามที่ต้องตอบก่อนลงมือ Phase 2+

Q1
“ใบเตรียม” และ “ใบหยิบ” ต่างกันอย่างไร ใครเป็นเจ้าของ และจังหวะไหนที่ reserve / issue stock?
Q2
“ใบกำกับ” มาจากระบบนี้หรือ ERP และแก้/ยกเลิกหลังจ่ายแล้วด้วยเอกสารชนิดใด?
Q3
โอนย้ายในคลังเดียว, ข้ามคลัง และข้ามบริษัทต้องรองรับแบบใดบ้าง? ใครถือ ownership ระหว่าง In Transit?
Q4
Production ใช้ BOM/route/version จากระบบใด และเป็น make-to-order, make-to-stock หรือทั้งคู่?
Q5
QC ต้องใช้ AQL/SPC ตั้งแต่ MVP หรือ checklist + maker–checker disposition เพียงพอสำหรับ pilot?
Q6
Opening stock ต้องมี cost หรือ quantity-only? ระบบเดิมให้ไฟล์ระดับ SKU–lot–location–tag ได้หรือไม่?
Q7
รถเป็น fleet ภายในหรือ transporter ภายนอก? GPS มาจาก provider ใด และเก็บตำแหน่งนานเท่าไร?
Q8
HR ต้องเชื่อม payroll หรือเป็น attendance/leave only? กฎกะข้ามวัน OT วันหยุด และลาเป็นอย่างไร?
Q9
Approval threshold อิงจำนวน มูลค่า เปอร์เซ็นต์ หรือชนิดสินค้า และต้องแยกตาม tenant/warehouse หรือไม่?
Q10
ผู้ใช้ pilot, SKU/lot/location, transaction ต่อวัน, concurrent scanners, label printers และสภาพ network จริงมีเท่าไร?
