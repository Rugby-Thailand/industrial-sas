# Design-sheet audit fixes · 15 October 2026

Resolves the 21 observations in the [reviewed audit](../../reviews/design-sheet-kiro-audit-2026-10-15/reviewed-audit.md) and [reviewed findings](../../reviews/design-sheet-kiro-audit-2026-10-15/reviewed-findings.json), using their qualifications. Scope: the standalone sheet in `docs/design-sheet` only. No `src/`, `convex/`, route, navigation-contract, `package.json` or lockfile change. `sheet.js`, `styles.css` and `tokens.css` are byte-identical to the pre-fix baseline, so the frozen variants stay exact. Historical audit artifacts are unchanged.

Approved constraints kept: 32px fine-pointer / 40px touch fields, centered stationary in-field icons with no hover fill or press movement, color-only hover/press for text buttons, real Radix Select/Popover and react-day-picker popups, the 2026-10-09 palette, type, layout and synthetic demo content.

## Resolutions

**DS-A01 · P1 · Confirming the selected date cleared it.** The calendar is always `required`, so confirming the selected day keeps it and closes the popup. Clearing happens only through **Clear date**, which appears only for optional dates (`data-sheet-clearable`) that have a value. Evidence: DS-A01 assertions (Enter and click on the selected day keep `2026-10-14`, popup closes, focus returns, scan delivery date and filled count survive, Clear date clears, no Clear for an empty value). Probe: `A_afterEnterOnSelectedDay.sourceValue` changed from `""` to `"2026-10-14"`.

**DS-A02 · P2 · Time committed on every choice.** Hour and minute are a popup draft, seeded from the committed value each time the popup opens. Only **Done** commits; Escape, an outside click or a lock discards the draft. Evidence: DS-A02 assertions. Probe: `timeCommitBeforeDone.valueAfterEscape` changed from `"23:30"` to `"08:30"`.

**DS-A03 · P2 · Thai years disagreed.** Thai uses `react-day-picker/buddhist` with `numerals="latn"`; the trigger uses `th-TH-u-ca-buddhist-nu-latn`. Trigger, caption, grid name and day names now all read 2569, while values stay Gregorian `YYYY-MM-DD`. Weeks start on Monday, and English uses en-GB. Evidence: DS-A03 assertions; caption and grid `ตุลาคม 2569`, selected day `วันนี้, วันพุธที่ 14 ตุลาคม 2569, เลือกแล้ว`, and a Thai selection stores `2026-10-15`.

**DS-A04 · P2 · Pressed states were invisible.** The view switch no longer uses the unstyled `secondary`/`ghost` classes; it uses `btn outline` with `aria-pressed`, like the capture-method and Filters toggles. `.btn.outline[aria-pressed="true"]` uses the selected surface with a link-colored edge and ink (the application's `active` variant), plus an outline in forced-colors mode. Disabled pagination uses `btn quiet`. Evidence: DS-A04 cascade assertions for the capture method, catalogue view and Filters.

**DS-A05 · P2 · Reading lock looked inconsistent.** Disabled text and search inputs use the disabled surface, ink and divider edge, matching the disabled pickers. Disabled quiet and in-field icon buttons stay transparent and change only ink. Evidence: DS-A05 cascade assertions (input, neighboring select, scanner).

**DS-A06 · P3 · Pending looked disabled.** HR **Pending write** and the Controls saving specimen are real buttons with the primary surface, `aria-busy="true"`, `aria-disabled="true"` and a progress cursor. Activation is ignored, and `disabled` is kept for unavailable actions. Evidence: DS-A06 assertions; probe `H_pending` changed from `disabled:true, ariaBusy:null` to `disabled:false, ariaBusy:"true"`.

**DS-A07 · P3 · Focus and selection shared a fill.** A highlighted option has the accent fill; a checked option has the check icon and 600 weight with no fill. Forced-colors mode adds an outline. Evidence: DS-A07 assertions (Radix separates the two states after ArrowDown; the cascade gives each its treatment).

**DS-A08 · P2 · Dark inks survived print.** The print block in `review.css` resets every dark-only variable the sheet uses (`--sheet-status-*`, `--token-disabled*`, `--muted*`, `--accent*`, `--ring`, the hover and contrast tokens and the remaining scene tokens), and it overrides the `.dark .badge.accent` and `.dark .badge.app-success` rules. `beforeprint` removes `.dark`, so the palette readout prints light values, and `afterprint` restores dark mode. Evidence: DS-A08 assertions. A resolver walks every `var()` the sheet uses through its token aliases and finds no unresolved dark-only variable. With the new print block removed, it flags the 10 audited variables. Rendered print output is still untested.

**DS-A09 · P2 · Tailwind contracts were inert.** The sheet now uses an honest, scoped component-CSS adaptation. `ui/select.tsx`, `ui/select-control.tsx`, `ui/popover.tsx` and `ui/calendar.tsx` keep the shadcn/Radix structure and `data-slot` names but contain no Tailwind classes. The bundle imports no `src/` code. Vite loads no PostCSS/Tailwind configuration, and react-day-picker's default stylesheet is gone. `controls.css` styles the placeholder, invalid, disabled, pending, read-only, focus, highlight and checked states. [DESIGN.md](../DESIGN.md#styling-ownership-and-tokenstate-parity) documents token and state parity with `select.tsx`/`buttonVariants.ts`. Evidence: DS-A09 assertions (no `@/` imports, no utility class strings, no `--tw-`/variant strings in `dist`, muted placeholder ink).

**DS-A10 · P3 · Missing differences list.** [DESIGN.md › Preview and application differences](../DESIGN.md#preview-and-application-differences) records each item as intentional, aligned, open or a preview proposal: styling, palette, menu-item height, calendar day size, the Filters button beside a field (still open question 1), the synthetic "today", example-only bounds, pending and read-only pickers, week start, Thai years and the time draft. The application plan is unchanged.

**DS-A11 · P2 · Empty time was latent and undefined.** Only complete `HH:mm` (`/^([01]\d|2[0-3]):([0-5]\d)$/`) counts as a time; anything else opens with both parts empty. **Done** stays disabled until both parts are chosen and the popup says what is missing. Optional times offer **Clear time**. A new **Empty · optional** specimen exercises this. Evidence: DS-A11 assertions. Probe: `C_minuteFirst`/`C_hourFirst` changed from `":45"`/`"09:30"` to `""`, and `C_emptyTimeOpen.minuteTrigger` changed from `"30"` to `"mm"`.

**DS-A12 · P3 · Calendar defaults leaked.** Without react-day-picker's stylesheet, days share one 14px size and weight, the lucide chevrons stay unfilled, and weekdays and outside days use muted ink at full opacity. Evidence: DS-A12 assertions. The 4.09:1 figure was arithmetic, and the new ink is not browser-measured.

**DS-A13 · P3 · Error returned after a locale switch.** `#required-error` no longer uses `data-i18n`. `review.js` derives it, and the specimen errors, from the current value on input and on every language change. Evidence: DS-A13 assertions. Probe: `D_requiredErrorAfterLocale.errorAfterLocale` changed to `""`.

**DS-A14 · P3 · A script failure hid the fields.** While the bundle loads, sources retain their space without exposing native picker UI. If mounting fails, a localized notice explains the error and review.js shows labelled read-only fields containing the committed values. Source selects remain hidden and outside the tab order, including after locale or workflow changes. Evidence: seven DS-A14 assertions plus a T3 browser check with controls.js deliberately returning HTTP 503. This replaces Kiro’s initial native-fallback proposal to honor the user’s explicit requirement.

**DS-A15 · P3 · Names omitted visible labels.** The language button is named `ไทย · Switch language` / `EN · เปลี่ยนภาษา`, with `lang` on the visible label. The theme button keeps one name (`Dark mode` / `โหมดมืด`), and `aria-pressed` reports its state. The filter chip is named `Remove filter: <visible label>`. Evidence: DS-A15 assertions.

**DS-A16 · P3 · English names in Thai mode.** The wordmark, section navigation and workflow tablist names and the proposal date (`9 ตุลาคม 2569`) are localized. The saving specimen is a busy button named by its localized text, with no `aria-label` on a role-less span. Evidence: DS-A16 assertions.

**DS-A17 · P3 · Loading totals were bare ellipses.** The statistics strip has `aria-busy="true"`; each value shows an `aria-hidden` ellipsis and visually hidden “Loading” / “กำลังโหลด” text. Evidence: DS-A17 assertions and the updated `check-adoption.cjs` loading assertion.

**DS-A18 · P3 · Public assets were copied.** `publicDir: false`, and the earlier `dist/` (with copied WASM, reference pages, icons and manifest) was replaced by the clean build. A post-minify `eslint-disable` banner keeps repository ESLint off the generated, git-ignored bundle. Evidence: DS-A18 assertions (`dist` holds exactly `controls.css` and `controls.js`) and `pnpm lint` passing with `dist/` present.

**DS-A19 · P3 · Tests missed the picker failures.** `check-controls.cjs` grew from 18 to 159 assertions, with cases for every reproduced failure and the missing states. It runs structural axe (13 rules, including `aria-prohibited-attr` and `nested-interactive`) and ID/ARIA/label integrity with the mounted controls closed and with date, time and listbox popups open, in English and Thai. `check-adoption.cjs` now states its vanilla-only surface, names its dates as revisions (`adoptionRevisionDate`, `adoptionGitBase`) and records the run's `gitHead`. The in-sheet adoption copy includes the 2026-10-15 text-button rule. HEAD is still `733c6aca` because nothing was committed.

**DS-A20 · P3 · State matrix incomplete.** A new **Field states** block in the Controls chapter shows invalid date, invalid time, example-range date (5–23 Oct 2026, labelled as an example only), empty optional time, pending select, pending date, read-only text, read-only date, disabled select and disabled time. Its note says the requirements and ranges are not business rules. Scan ticket dates remain unbounded, and no future-date or MFG/Delivery policy was inferred. The disabled ticket controls in the Reading state remain. Evidence: DS-A20 assertions.

**DS-A21 · P2 · The calendar overflowed short viewports.** Picker popups use `max-height: min(var(--radix-popover-content-available-height), calc(100dvh - 24px))` with `overflow-y: auto` and `overscroll-behavior: contain`. Evidence: DS-A21 assertions (Radix supplies the variable; the rule exists). Parent T3 measurement at 640×320 confirmed the popup fits within the viewport, uses internal scrolling, and exposes Clear date after scrolling.

## Remaining limits and follow-ups

- Rendered print, physical touch devices, actual screen readers and production application flows remain untested. Browser checks are scoped to the documented viewports and interaction paths.
- The Review-state keyboard follow-up was reproduced and fixed by the parent. Enter selected an item, the vanilla handler remounted/focused its trigger, and the native Enter default action clicked that new trigger, reopening the listbox. The sheet Select content now consumes Enter after the item handles selection. Three regressions and native T3 keyboard confirmation pass: the new value is selected, the menu stays closed, and focus returns to the new trigger.
- The pending-select treatment (focusable and not disabled) and read-only pickers are preview proposals. The application's `SelectControl` still disables a pending trigger, so neither has been adopted.
- The calendar's "today" is a fixed synthetic 2026-10-14 so the preview is reproducible.
